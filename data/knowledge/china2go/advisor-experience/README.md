# 顾问经验第一批试验

本目录是可编辑、可停用的经验数据，不是模型训练集，也不是已批准的新产品事实。

`library.json` 当前为 `pilot`。只有隔离评估环境、客户发送关闭、
`RECEPTION_ADVISOR_EXPERIENCE_ENABLED=true` 时才加载。默认开关关闭，
生产环境不读取 pilot。真实模型对照及业务效果审核完成之前不得改为 active。

## 内容归属

- `conversation_method` 只记录理解、澄清和承接方法，不绑定或携带产品事实。
- `route_method` 为每条适用线路显式配置 `route_fact_ids`。引用的是当前线路包事实，
  没有复制旧价格、酒店名单或航班数据。新线路不自动继承。
- 一个引用缺失时，仅跳过该条经验，不停用现有问答、不转人工。
- 模型结合实际问题决定是否借鉴。程序不按客户关键词选择经验，也不对输出做句式匹配、删句或扩写。
- 比较线路时通过现有 `load_skill` 分别读取，两条经验各有线路标识；比较不自动切线。

## 来源和审核

来源为 `China2Go_转人工场景与顾问答复_待审核_20261030.xlsx` 的场景 ID 和会话 ID。
原始问答、消息 ID 和完整后续保留在该工作簿，客户身份与联系方式不进入经验正文。
本轮只提炼 5 类方法：用餐、车辆、交通、住宿和需求澄清。
顾问提及的临时库存、报价、订金、未经确认设施、医学推断不作为学习事实。

2026-11-01 真实模型试验后，整体仍未达到上线标准，继续保持 pilot 和默认关闭。
用餐经验已单独停用：试验出现了无事实依据的餐厅协助承诺；停用后仍有同类输出，
不能把问题简单归因于某条经验，也不能把取消某个自动断言当作修复。
其他方法仍有多问、展开过度和偏好推断波动，详见 `docs/development/advisor-experience-pilot-20261101.html`。

修改时更新 `version`，记录审核说明，检查每条线路引用，设置 `review_due`。
过期、暂停或文件格式错误时回到原有接待。`enabled=false` 可单独停用一条。
不得用 `conversation_method` 绕过线路适用范围写入具体服务承诺。

## 测试与记录

运行 `backend/tests/test_advisor_experience.py` 检查隔离、停用、证据和运行时行为。
真实模型对照使用相同生产资料快照，分别关闭/开启试验开关。
必须检查跨线路、多轮、纠正需求、只问一项、拒绝留资、明确暂停和人工接管。
否定句、客户疑问与偏好等语义需查看原文，不能以子串命中直接断定违规。
测试用例里的 `manual_checks` 是必须记录结论的复核项目，不表示自动通过。

运行日志 `advisor_experience` 记录版本与已提供的经验 ID，
`provided_not_verified_used` 只表示已提供给模型，不能算作模型实际采用或客户问题已解决。
