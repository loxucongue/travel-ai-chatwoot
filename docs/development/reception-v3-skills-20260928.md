# V3 Skill 结构与真实加载修正

此前 V3 把两条线路和通用说明整包注入提示词，没有标准 Skill 元数据和按需工具加载。本次替换该实现，不新增配置页面或话术审核器。

## 当前实现

- 三个独立目录：`tibet-reception`、`peach-9d-2027`、`peach-11d-2027`。每份 `SKILL.md` 有 YAML `name`、`description`、场景与处理方法。
- 直接用本地参考仓库 Commerce Agents 的 `SkillRegistry.from_dir` 检查，三个目录均成功加载。业务正文不复制电商流程。
- 通用接待和已选线路预加载。未选线路只提供名称、别名和 Skill 索引，模型通过原生 `load_skill` 获取完整正文；比较时同轮读取两条。模型仅返回线路选择、尚未加载正文时，运行时先激活该线路再完成决策，避免虚报已加载。
- 后台仍是唯一业务数据来源。加载时将当前原文、完整 SOP、场景示例、事实、图文顺序及素材引用附入 Skill；修改配置后下一次读取即生效。正在发送的计划维持原快照。
- 官网补充资料由 `get_service_facts` 按需返回，不默认混入每次请求。
- 最终文字没有事后话术审核和改写。保留一次 JSON 结构修正与有限工具回合；开场和完整 SOP 仍按配置原文定时交付。
- `loaded_skills` 记录实际正文摘要；`skill_tool_calls` 记录工具参数与结果。日志中的 `script_ids` 是模型的引用声明，不能等同于每个字都来自原文。
- 移除旧的根目录 `SKILL.md` 和整包提示词拼装。发布摘要改为包含子目录；发布和回滚同步依赖清单，PyYAML 声明为直接依赖。

同一配置快照、未附官网和素材清单的离线比较：旧系统提示词 44,173 字符；新未选线 5,394，9 日 13,827，11 日 14,642。这里只衡量输入大小，不把它换算成延迟或效果保证。
