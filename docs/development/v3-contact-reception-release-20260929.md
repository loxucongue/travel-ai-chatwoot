# V3 四人话术、留资与沉默跟进优化

本轮针对模拟客户 #588，以及客户已提出的四人承接、LINE/Email 留资和沉默跟进问题。保持 V3 单主模型；没有增加话术审核模型、关键词替换或发送后改写。

## 改了什么

- 两条线路的 `group_party` 保留公司小团定位、4–6 人团型、可考虑自己一团的原话。介绍结束后只去掉“先介绍行程”的过期衔接，不增加“独立成团同价”的承诺。
- 完整介绍和当前问题回答之后，可以首次邀请一种联系方式；日期未定、需要和家人讨论，不再成为必须等客户决定报名的理由。
- 已邀请但未回应时继续答疑，不因客户又报月份或人数而重复追索。客户指定 Email 就索取邮箱，给出实际联系方式后交接；明确要求真人可以直接在当前会话交接。
- 其他月份采用 `consult_advisor`：说明当前产品日期，承接候选月份，不虚构九月团期，也不把整个三月说成都在 3/20–4/10 内。后台仍可选择其他处理方式。
- 新增四条可编辑通用场景原话，删除一条与新配置冲突的旧“产品不匹配直接转人工”测试指令。原开场和沉默设置不随这次配置更新改变。
- 历史对话以真实 user/assistant 角色输入，附件显示实际交付引用；不再让上一轮内部 reason 混入接待判断。
- 主模型使用 Flash 的低强度思考，保留工具续轮所需的 reasoning_content，最终只发送模型的可见正文。不是新增第二个审核器。
- 修复比较线路时另一线路素材被误判不匹配的问题。按素材所属启用线路解析附件，客户当前选线不因此改变。
- 可选 `script_id` 接受 null。没有引用原话时不再因此重新请求模型，正文保持不变。
- 沉默可以补充相关事实、问一个尚未问过的有用问题或首次邀请。已问未回应、已答的事实，不因经过几分钟就变成新内容。

## 验证方法

固定八段关联长对话，补 #588 多月份、Email、客户反向加顾问、拒绝联系四段，共 12 个场景。每段从线路名称作为客户第一条消息开始，完整走配置开场、介绍、关联追问；四人消息在介绍进行中插入。检查实际交付、客户状态、后续计时与交接，而不是每个会话只问一句。

三个迭代批次各启动这 12 段。随后只复验失败及邻近边界：比较、#588、Email、短对话沉默、直接要求真人。每批原始失败保留，重试成功不抹去第一次失败。

模型调用使用真实 `deepseek-v4-flash`；独立 SQLite、模拟渠道，出站关闭。3 分钟、5 分钟使用墙钟等待，未加速时间。测试副本临时设为 [3,5]，不把生产原 [1,120] 改成测试值。客户明确预约五分钟时由模型设置该次预约。

原始长对话、输入快照、模型调用和费用账本保留在本地 `output/effect-iterations/v34-contact` 至 `v38-contact`。这些批次名称只是测试编号，系统仍然是 V3。原始客户资料与运行数据库不提交 Git。

## 真实效果与未通过项

| 项目 | 证据与判断 |
|---|---|
| 四人原话 | 后续批次均保留核心三层信息，没有缩成几个字；有些轮次仍适配称呼和人数。介绍完成后不再说“接下来先介绍行程”。 |
| 首次留资 | #588 复现会在介绍后或家人讨论后主动邀请 LINE；尚未给联系方式时继续接待，没有提前交接。 |
| 避免追索 | 早期非思考批次仍随每次新话题重复邀请，判失败；改真实对话角色并使用低强度思考后，#588 复测只邀请一次，后续月份问题正常承接。 |
| Email | 实际五分钟后提醒邮箱；客户给出测试邮箱后保存 Email 和实际地址，handoff=true、下一触达为空；不再要求 LINE。 |
| 反向加顾问 | 使用当前知识中的官方 LINE，未捏造账号。客户自报已加可交顾问，但这不是已验证加好友成功，测试没有渠道好友回执。 |
| 其他月份 | 说明九月不属于当前桃花产品，继续问月份或偏好，保留候选需求；没有承诺九月一定有团。 |
| 直接要真人 | 新增“直接转真人，在这里聊、不留电话”场景，立即 handoff，没有先逼客户留电话。 |
| 比较与素材 | 早期 `material_route_mismatch` 确认是程序缺陷并修复；比较期间保持原选线，另一线路素材可解析。 |
| 输出格式 | 复验发现一次可选引用 null 导致失败及重试；修改字段定义，并以无需重试、正文不变的测试验证。 |
| 自然度 | 四人原话与联系方式用途更贴合业务。但普通比较仍有偏长、重复衔接，少数批次仍出现“標間”等说法；未达到“九成话术经业务盲评可直接发送”的正式门槛。 |

不能把这些测试换算为真实获客转化率。台式语气仍需业务顾问评价，也不能据此宣称此前全部业务需求均已达标。
