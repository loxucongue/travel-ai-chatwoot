# 独立 V3 演练版交付

V3 已作为独立引擎接入原演练场，默认新建时选择 V3，可切回 V2/V1。正式 297 个客户会话仍使用 V2，没有向客户发送测试消息。

## 实现

- `app/reception_v3` 独立主模型、Skill 编译、状态和事件调度。复用配置、素材与模型 HTTP 传输，不调用 V2 业务分类、话术审核或裁剪。
- 两条线路的事实、SOP 原文、顺序、图片和场景话术从现有线路配置编译；通用话术及官网知识同时提供。
- 客户首次进入原样发送配置开场，不按问候关键词判定。泛咨询在已发送选线问题后等待，不追加模型开场；确认线路后启动完整 SOP。
- SOP 逐条按间隔交付。普通插话排队；模型判断中止、改线或转人工后取消剩余计划。整套介绍完成会再次运行同一个模型，回答期间问题，并在最后问合适的信息。
- 默认按通用沉默间隔运行模型；模型决定发送、等待、预约或结束。时间从交付后开始，客户新消息取消原定时；拒绝主动联系后仍可被动答疑。
- 已发送、待发送、队列问题和完成状态保存在原演练数据库。V2 Worker 不消费 V3。图片按素材 ID 引用，不由模型编 URL。

## 验证证据

工程：初版全量后端 1477 通过、52 跳过；后续状态、计时及兼容改动定向 43 通过。前端现有测试 1 项和最终构建通过。桌面、390px 手机布局和引擎切换做了浏览器检查。

真实模型连续验收使用独立数据库，只复制配置和素材，不复制客户对话，不调用 Chatwoot。保留初轮失败和修复记录。最终两条长对话各 9 次事件决策，加一条默认沉默旅程 5 次决策：

| 场景 | 实际结果 |
| --- | --- |
| 9 日、人数未知 | 完整介绍后答机票和集合问题，最后问几位 |
| 11 日、期间补充两位 | 保存人数，介绍完成后统一答疑，改问出发时间 |
| 房差和供氧关联追问 | 根据所选线路回答房差，区分车内和房间供氧 |
| 约定三分钟 / 五分钟 | 实际墙钟等待后触发，承接约定问日期，没有重发介绍 |
| 没有客户预约 | 配置一分钟到期后确实运行模型，模型判断刚问过人数，暂不重复发送，延后评估 |
| 留微信并要求核余位 | 写入沙盒交接状态，停止后续主动评估 |

最后对泛咨询入口补了两次真实模型复验：配置开场后等待、随后选 11 日启动整套介绍。

上线沙盒 #574 保留了发现“额外泛问候”的失败证据；修正后 #575 已完成配置开场 → 客户选 11 日 → 完整介绍 → 末尾问人数。两份沙盒都在测试后停止，避免留下无人观察的主动任务。不能将 #574 当作最终通过样本。

累计真实 HTTP 请求 52 次（包含失败、复测和上线沙盒）；输入 1,649,625 token，输出 9,473 token。按项目费用账本的峰值单价、缓存命中结算合计 ¥1.85946792。不是提供商账单核销金额。

## 当前边界

这是可运行、可连续验收的独立 V3 沙盒版本。正式 Chatwoot 交付、真实人工任务与手机通知尚未接入 V3，未宣称生产客户已切换。

移除审核后，模型表达仍会有波动。测试中还可见原资料用词「標間」、不必要的补充，以及连续追问日期等文案改进空间。这轮证据证明主链和具体场景运行，不能等同于历史所有话术要求全部达标或业务盲评通过。后续主要修改这一份 Skill 和线路话术，不再加多层审核器。
