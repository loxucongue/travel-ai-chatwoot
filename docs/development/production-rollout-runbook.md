# AI 接待生产放量手册

更新时间：2026-09-04

## 当前状态

- 分层实时接待：`split-realtime-reply-v33`
- 分层沉默跟进：`split-silence-touch-v10`
- 全局消息发送总开关：关闭
- 真实 SOP 范围：`allowlist`
- 真实 SOP 白名单：会话 `#26`
- 大团转人工阈值：读取运营页面当前已发布值，当前为 8 人

AI 演练场已经可以使用，但演练通过不等于允许真实全量发送。

## 推荐放量顺序

### 阶段 1：AI 演练场

使用隔离模拟客户验证：

- 未选线路和线路二选一；
- 9 日、11 日问答与线路切换；
- 价格、住宿、车辆、证件和多问题；
- 7 人继续接待、8 人转人工；
- 提供联系方式后转人工；
- 拒绝联系、投诉、退款、要求真人和附件场景；
- 通过“测试下一次跟进”检查沉默内容、图片、重复问题和结束条件。

### 阶段 2：指定真实测试会话

保持全局发送关闭或受控总开关，只将明确的测试会话加入白名单。必须记录测试前消息数和真实出站数，并逐条检查 Chatwoot 实际发送状态。

### 阶段 3：少量新客灰度

演练场和真实测试会话通过后，再按指定 Inbox、标签或名单逐步扩大。不要给历史会话批量补标签，也不要让新策略追溯执行旧沉默任务。

### 阶段 4：正式启用

只有在业务方明确批准范围后才开启全局发送。开启前再次核对人工排班、接管 SLA、Facebook 回复窗口和停止方式。

## 实时接待链路

```text
客户消息
-> Webhook 持久化与幂等
-> 代码发送安全门
-> 客户理解模型提取候选语义和证据
-> 代码业务规划器确定线路、动作、阶段和转人工
-> 代码筛选允许事实和素材
-> 回复生成模型生成自然话术
-> 事实核验模型检查事实蕴含
-> 代码做长度、素材、并发和发送校验
-> Chatwoot 发送或转人工
```

## 当前业务规则

- 大团阈值不是提示词常量，来自“AI 接待策略”页面。当前发布值为 8 人。
- 模型只提取客户人数候选和逐字证据，代码判断 `party_size >= 8` 后执行转人工。
- 有效联系方式、明确真人请求、投诉退款、合同争议和必须查看附件均由代码转人工。
- 客户明确拒绝继续联系时停止自动接待。
- 线路允许列表来自当前启用线路，不在修复提示词中硬编码。

## 沉默跟进

- 未选线路：30 分钟后最多一次低压力线路选择跟进。
- 已选线路：按当前发布的 `1/3/5/10/30/60` 分钟相对节点推进。
- 客户回复后取消旧节点。
- 已覆盖内容和已发素材不重复。
- 已经问过但客户未回答的必需字段，下一节点不重复或换问另一个字段。
- 人工接管、取得联系方式、拒绝联系或安全门阻断后停止。

## 每次真实放量前检查

1. 后端回归、真实问题回放和演练场测试通过。
2. 全局发送开关和白名单与本次批准范围一致。
3. API、Worker、Playground 服务为 active。
4. `pending_webhooks=0`、`dead_webhooks=0`。
5. 记录消息数和真实出站数基线。
6. 确认 Chatwoot 人工接管和停止 AI 的操作方式。
7. 测试客户新消息能取消待发送沉默任务。
8. 测试人工抢先回复后 AI 不再提交旧结果。

## 回滚条件

出现以下任一情况应立即关闭全局发送并停止扩围：

- 重复发送或人机同时回复；
- 线路、价格、日期或图片明显错配；
- 8 人阈值没有按配置执行；
- 客户拒绝后仍继续触达；
- Webhook 队列持续堆积或 Worker 心跳停止；
- Chatwoot 返回未知发送状态且系统重复提交。

回滚后保留数据库、发布包、模型调用和发送记录，用同一案例在演练场复现后再重新发布。
