# V2 发布核对与回滚

本文件对应此次 V2 整改。旧 `production-rollout-runbook.md` 中的版本、阈值和沉默间隔是历史状态，不能作为此次 V2 的配置依据。本文是操作方案，不代表已经部署或允许向客户发送。

## 发布单位

一次发布必须绑定同一份代码摘要、线路 Skill、事实库、运营配置、已批准素材文件哈希和模型配置。候选包位于 `output/v2-completion-20260920/release-final-*`，只允许采用完整验收通过且没有 STOPPED 标记的版本。`acceptance-status.json` 的 accepted=false 或测试 incomplete 均不得解释为验收通过。

代码包是覆盖包，不是数据库备份。本工作目录没有 Git 元数据，以文件摘要及压缩包摘要标识版本，不能声称已提交 Git。

## 发布前核对

1. 核对完整同版单轮、连续旅程、独立审核、服务扩展、后端回归、前端构建和逐文审阅；失败、超时与冷启动均计入性能，不能挑选最好的一次。
2. 保存生产当前代码包、数据库一致性备份、配置和素材清单；先验证备份可读，再进行替换。保留 V1。
3. 核对通用知识使用此次验收的内容哈希。本地待审修订 5 包含 31 条事实、10 个模块；当前已发布修订 3 仍限演练。修订编号是本地编号，不能在其他环境按数字直接发布，必须按内容哈希核对。
4. 高原资料必须是内容获准、哈希一致、可读取的 PDF。隔离浏览器测试的批准操作只证明功能，不能作为实际内容批准。缺素材转人工是故障承接，不等于附件要求完成。
5. V2 普通沉默间隔取发布配置，当前验收默认 1/120 分钟，从实际交付起算；预约、考虑等待、渠道窗口、拒绝和人工接管分别门控。不得套用 V1 的旧节点时间表。
6. 初次安装保持全局发送关闭，先验证服务启动、版本摘要、配置与素材读取、队列及 Worker。此次任务没有执行真实渠道发送，因此没有真实渠道回执证据。

## 受控启用

业务确认的范围内逐步启用新客；避免批量迁移历史会话或补发旧沉默任务。核对每轮资料保存、实际出站记录、附件回执及人工待办，不以模型生成成功代替交付成功。全局开关与渠道权限仍是最后一道执行门。

## 回滚

- 出现事实或图片错配、拒绝后触达、未知提交重复发送、客户资料错存、必要人工任务缺失时，先关闭发送，保留现场记录。
- 切换单个会话引擎应使用现有版本校验接口 `/automation/conversations/{conversation_state_id}/engine`，提交目标 engine_version 和读取到的 expected_version。版本冲突重新读取后处理，不绕过保护直接改数据库。
- 该接口取消旧引擎任务并投影可信客户事实、实际交付与人工状态。切回 V1 后不能恢复 V2 的旧待发结果，也不能把未交付内容标为已答。
- 如需回退代码，使用发布前备份及其配套配置；数据有新写入时先评估兼容性，不能直接用旧数据库覆盖新客户记录。
- 复盘保存客户触发消息、版本摘要、审核与改写记录、任务状态和实际回执；以同一输入复现后重新验收。

## 本次边界

真实客户消息发送数为零。完成代码和隔离测试不等于生产渠道已验收；能否发布必须由最终同版报告和实际素材批准状态共同决定。
