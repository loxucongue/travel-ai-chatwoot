# V2 Agent 重构开发方案

## 目标

面向公域低到中意向旅游客户，把 V2 从“按固定 Flow 回答问题”逐步改成“主 Agent 理解完整需求、调用线路能力、介绍和比较线路、建立兴趣、适时留资并交人工”的接待系统。

业务目标仍然是：

```text
理解需求 -> 匹配线路 -> 完整介绍 -> 亮点和顾虑处理
-> 自然取得联系方式 -> 人工接手
```

沉默客户由同一个 Agent 结合 Journey Memory 判断是否有新的相关价值，不因为计时到点就机械发送。

## 设计边界

- Commerce Agents 只借鉴运行时组织方式，不照搬购物车、结账和高意向购买流程。
- 保留 V1 兼容和现有 Chatwoot 交付层；本次替换的是 V2 的决策能力。
- 线路事实来自已发布线路包和 Backend 工具，模型负责理解、比较、推荐和表达。
- 不继续增加大量硬编码分支。Flow 只作为上下文提示，不能锁死 Agent 的任务判断。
- 结构化输出服务于文字、资料、比较和下一步建议；实际发送仍由现有交付计划处理。

## 已完成阶段

### Stage 1: 线路 Backend 与结构化呈现

已提交 `6cb6551`。

- `search_routes`：按天数、预算、珠峰等条件筛选已发布线路。
- `compare_routes`：按价格、节奏、住宿、景点、交通和供氧等维度比较线路。
- `get_route_details`、`get_route_material_packet`：读取线路详情和资料包。
- 决策支持 `route_comparison`、`route_details`、`itinerary`、`route_materials`、`suggestions`。
- 前端演练和运行记录可以展示这些呈现结果。

### Stage 2: 并行工具调用

已提交 `2584344`。

- 同一轮无依赖工具最多并行 4 个。
- 保留调用顺序和错误语义，结果仍按模型请求顺序归并。
- 记录 `parallel_batch`，可定位并行批次和耗时。

### Stage 3: 任务型接待 Skill

已提交 `12460b3`。

- 新增 `new-lead-intake`、`route-matching`、`route-presentation`、`value-building`。
- Skill 描述适用场景、工具、步骤、延伸方式和结束条件。
- V2 会按当前线路和旅程上下文提示相关 Skill，但不把提示当成硬路由。

### Stage 4: 响应协议和运行元数据

本阶段包含：

- 统一 `response`、`delivery`、`customer_events`、`memory_updates` 和 `handoff` 结构。
- 工具规格缓存，避免每轮重复构造静态工具描述。
- 对响应协议增加回归断言。

## 后续阶段

### Stage 5: 主 Agent 任务编排

把当前“模型多轮 JSON + 审核修订”收敛成一个清晰的任务循环：

```text
读取上下文和 Skill 索引
-> 主 Agent 识别客户目标
-> 并行查询线路和资料
-> 生成文字、呈现、资料和下一步
-> 记录旅程状态
```

标准线路事实问题优先走一次模型回合；复杂复合问题才继续工具回合。事实审核保留，但不再对每个普通回答默认触发多轮修订。

### Stage 6: 交付适配

- 将结构化呈现映射到现有文字、图片、PDF 和交付计划。
- 行程图、景点、酒店、车辆继续遵守线路资料顺序。
- 比较和推荐结果先输出文字摘要，再按客户兴趣补资料，避免一次倾倒全部内容。

### Stage 7: 留资和沉默培育

- 主 Agent 根据客户意向和已解决问题决定是否自然询问一种联系方式。
- 留资成功后立即交人工，停止自动销售。
- 沉默触达复用主 Agent、Journey Memory 和 `silence-nurture` Skill，只补充未解决且有新价值的内容。

### Stage 8: 效果验收

覆盖四类对话：

1. 多条件线路匹配和比较；
2. 明确线路后的完整介绍和亮点延伸；
3. 顾虑处理、留资和人工交接；
4. 考虑、沉默和主动回来继续咨询。

每条同时评估：需求覆盖、推荐理由、台湾表达、资料计划、留资时机、模型轮次和端到端耗时。工程测试通过不等于业务效果通过，必须保留人工盲评。

## 当前差距

当前已具备线路工具、结构化响应、并行工具和任务型 Skill，但仍有四个明显缺口：

1. 主 Agent 仍受旧的严格决策协议和事实审核循环影响，速度和延展性未达到目标。
2. `presentations` 目前主要进入决策、trace 和演练展示，尚未成为 Chatwoot 交付协议的一等输出。
3. 工具调用已并行，但尚未实现 Commerce Agents 风格的流式参数到达即执行。
4. 静态 Prompt、Skill 索引和工具描述还没有完整的缓存与耗时指标。

因此，当前版本是“新 Backend 和 Skill 已接入的 V2 过渡版”，不是最终目标架构。后续开发应优先解决主 Agent 编排和普通回复的多轮审核开销，再扩展前端呈现和沉默培育。
