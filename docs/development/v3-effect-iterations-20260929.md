# V3 接待效果迭代总结

测试时间：2026-09-28 至 09-29（北京时间）。沿用 DeepSeek Flash 和真实 V3 演练执行链。

## 结论

完成三轮候选优化和连续对话复测。**有可保留的改善，但三版都没有达到整段接待稳定可直接使用的目标，不发布到生产。** 第三版改变历史消息组织方式后，没有稳定胜过第二版，已撤回这个实验。当前保留第二版的运行时、提示词和 Skill；这三份文件已逐字核对，与第二版隔离测试版本一致。

最明确的改善是：官网随身氧气事实不再漏读；两人总价能够直接计算；比较两条线路时可直接读取双方事实；配置保存不再丢失话术使用说明。仍未解决的是：留资时机、反复追问、未确认安排的推断，以及繁体中文虽通顺但仍有较重的模板感。

不能把这次结果写成“回复效果已全部修复”。179 项工程回归通过也不代表这些业务目标达标。

## 目标与方法

目标见 [迭代计划](v3-effect-iteration-plan-20260928.md)：

1. 台湾聊天语气自然，少复读；非 SOP 回答至少九成无需重写。
2. 首次回答解决有资料依据的顾虑，接住省略追问；未知安排不编造。
3. 高意向能主动邀请一种联系方式；未回应、拒绝、仍在顾虑阶段不追着索取。
4. 实际等待三分钟、五分钟；预约能履行，自然沉默有新价值才触达，拒绝和交接后停止。

每版使用八段关联主对话和两段重点复测。主对话从真实线路名称入口开始，经历开场、完整介绍，再连续询问价格、房差、住宿、健康、交通、意向和联系方式。八个客户的身份与目标固定，第一版分批阅读后继续追问，后二版复用同组问题，逐条等待上一轮交付完成。不是把单句问题拆成互不相关的新会话。

测试环境为服务器上的独立发布目录与独立数据库，仅只读复制线上配置、资料、素材。HTTP 限制只允许模型请求，禁止客户渠道写入。所有版本保留失败原文；没有让另一个模型给自己的回答评分。语气评价为本次逐条阅读，尚无台湾顾问独立盲评，不能据此给出客观“台湾感准确率”。

自然沉默副本采用间隔 `[3,5]`，即先等三分钟、再等五分钟；若首次决定停止，继续观察无新消息，不能假称第二次模型评估成功。客户明确预约的三／五分钟提醒单列。

| 顾虑处理 | 部分改善，未达标 | 氧气、总价、差价稳定改善；单房差范围在后两版改善。停车、酒店细节仍有无依据扩展，线路指代偶发退回入口线路 |

C3在明确要求顾问时已经停止AI；之后补充的LINE ID仍留在会话消息中，但没有继续由AI提取到profile。这符合接管后不抢答的行为，但不能将这类记录计为“联系方式已结构化提取成功”。

## 三分钟、五分钟的实际证据

- v31 R1：北京时间23:51:19最后确认预约，23:56:21发出LINE提醒，约五分钟。C4的三分钟预约被该案例1元测试预算的预留检查阻断，保留为失败，不计通过；三次阻断未发起HTTP请求。
- v31 C8：23:57:35第一次自然沉默评估选择等待；次日00:02:37再评估选择停止，没有强行重发线路或留资。
- v32：跨午夜后，C4/R1被复制来的营业时段顺延到早上，**没有在原预约时刻完成**。这不是模型话术正确的证明，也不计作三／五分钟提醒通过。
- v33：在隔离副本将C4/R1设为全天允许触达，客户重新预约，保持真实墙钟等待。C4于00:07:31确认，00:10:36发出9日预算提醒，约185秒；内容为两人19,960元及另留机票、正餐、小费，没有索联系方式。R1客户00:07:30重新预约，00:12:34发出LINE提醒，约304秒。
- C7/R2自然沉默没有新的波密酒店资料时选择不发。客户回来询问仍回答；C2/C5明确拒绝后再提问仍答，保留拒绝状态。

线上沉默开关与时段未修改。当前正式配置的 `live_enabled=false`。本轮证明的是隔离执行和文案行为，不是生产渠道或手机设备收件。

## 保留与撤回

保留：

- 官网通用事实和两条启用线路事实可见，减少“不查已有资料就说未知”。
- `usage_note` 在配置API保存、线路包、Skill编译之间完整保留；原有回归发现丢字段后修复。
- 修改过的业务话术标记为运营编辑，不能继续冒充官网逐字原文；对应内容组与场景话术同步。
- 纠正“航空母車”等源错字，留资模板改为一种联系方式。

撤回：

- v33历史消息分角色实验。它减少输入长度，但没有证明效果更好，且出现重要事实回归。完整实验提交与对话证据保留，当前代码回到v32输入组织方式。

未增加话术审核模型、字符串删句、关键词判定留资或固定流程兜底。本轮没有改后台UI、增加Worker或部署生产。

## 下一步优化应缩小变量

这三轮不支持“再堆一批提示规则就能稳定达标”的结论。下一轮应先做有对照的小实验：

1. 保持SOP原文交付不动，把答疑话术整理成少量明确的“场景、直接答案、适用条件”，减少同一价格／酒店／联系邀请在多处重复；先选停车、波密、户外氧气、房差、跨线报价、未回应留资这六类失败。
2. 同一模型、同一客户脚本，只比较完整资料加载与精简场景资料加载；如果仍不稳定，再单独对照模型推理模式，不能同时改提示、模型、知识后宣称找到原因。
3. 继续使用长对话和真实三／五分钟等待，新增未参与调参的顾问原话作盲测。先消除无依据承诺和拒绝后的重复索取，再评价九成文案无需重写。

这不是要新增平台或审核链；需要验证的是模型在简洁、明确的资料下能否持续做对接待决策。
