# V3 业务话术与长对话修正

日期：2026-09-30。范围：接回遗漏的通用知识，统一文档话术与线路配置，改善房型、年龄、健康答疑、留资交接和沉默判断。没有新增话术审核模型、发送后文本替换或前端页面。

## 业务口径

本轮用户明确确认：**以 AI.docx、AI(1).docx、AI(2).docx 提供的话术标准为主**。因此满75岁的台湾旅客按“可报名并提供健康证明”接待，超过75岁“不建议、需个案确认”。这是项目业务口径，不把它扩大为对个人健康适宜性或现实审批结果的保证。

- 9日希尔顿保留波密例外；11日保留波密、珠峰例外。
- 价格用“两人一房”“一个人住一间补单房差”，同步修改事实、SOP 和场景原话，金额不变。
- 多人优惠存在，但具体优惠金额未提供；小团升级不加价不等于没有额外优惠，也不等于包团同价。
- 65岁是健康证明条件，不是最低报名年龄；不能反推64岁免除文件或保证所有条件均满足。
- 人数不决定分房，客户希望的住法仍需确认能否安排；绒布独立卫浴不能推到所有住宿。

## 实现

1. `compile_skills()` 将已有服务知识和有效原话接入 V3。模型首轮输入及 `get_service_facts` 使用同一组服务事实；后台同 ID 的原话覆盖或停用仍有效。通用知识版本纳入 Skill 内容摘要。
2. 加入药品咨询、65岁并非最低年龄、超过75岁接待的短答；线路加入高反顾虑短答并明确75岁话术。匹配后可以直接引用 `script_id`，不必让模型重写。
3. “已加你们顾问LINE”按客户自报记录渠道、原文与 `self_reported_added`，交给顾问核实，停止 AI 触达。不伪造 ID，不把自报当好友验证成功。
4. 模型输入明确列出剩余沉默评估间隔；最后一次没有新帮助时结束，不再声称还有下一轮。无消息交付的等待，计时从模型评估结束起算。
5. 一次性配置修正脚本只处理已知旧原文，支持备份，保留其他运营改动及素材。发布包包含通用服务知识，预检实际编译 Skill，避免再次出现“文件在本地，线上未加载”。
