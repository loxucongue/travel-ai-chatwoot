# SOP 时间规则与本地内容组

## 当前入口

`http://127.0.0.1:4175/#/sops`，点击“新建 SOP”或已有策略的编辑按钮。

编辑器沿用现有抽屉、颜色和组件。桌面左侧编辑，右侧显示预计时间线；手机按顺序排列。头部与保存区固定，编辑内容单独滚动。

## 时间口径

| 规则 | 配置 | 计算 |
|---|---|---|
| 添加后 | N 分钟，例如 10、20 | 客户添加时间 + N 分钟 |
| 添加后第 N 天 | 第几天、时分 | 上海日历日；添加当天为第 1 天，不是每隔 24 小时 |
| 上一组发送后 | N 分钟，例如 10 | 本 SOP 上一组最后一条确认发送时间 + N 分钟 |

- 当前没有可靠的 Facebook 加好友时间。本地按已同步历史中，同一联系人在同一收件箱的首次公开客户消息计算；不使用本地导入时间。历史不完整时，这不保证是客户真实的首次接触时间。
- 演练客户在首次发言时确定添加时间，后续发言不会重置该锚点。
- 第一组不能依赖上一组。下一组必须等待前组全部确认；前组被阻断或取消，后组不会假定已经发送。
- 第 1 天的时刻早于客户添加时间时不会偷偷顺延到明天；预览提示冲突，执行仍检查过期宽限。
- “上一组”仅指本 SOP 的前一个内容组，不是整个收件箱的任意最新消息。
- 原有固定日期、入组时间、客户最后回复规则保留读取和执行兼容；编辑器不擅自改写旧策略。

## 内容组

每个策略最多 20 个时间节点；每个节点最多 10 条有序内容。支持新增文字、图片、视频，内容和节点均可上移、下移、删除。

- 文字：最多 10,000 字符。
- 图片：本地上传，页面预览，替换或移除；建议 PNG/JPEG/WebP/GIF。
- 视频：本地上传并播放预览；支持 MP4/WebM，具体编码需浏览器支持。
- 附件可带说明。单文件大于 0 且不超过 20 MB。
- 旧版音频/文件内容仍能读取，不强行转换。
- 文件保存到后端配置的 `data/uploads` 目录，SQLite 保存素材元数据和关联 ID，不接 OSS。
- 整组先校验全部附件；任意文件缺失或类型不匹配时，连同该组文字一起阻断。模拟执行按顺序记录各条确认状态，一组只占用一次主动触达频控。

## 安全边界

时间可配置不等于允许发送：仍保留客户回复退出、人工接管、标签、渠道窗口、联系时段、频控和有效期检查。SOP 与唤醒合计每联系人滚动至少 24 小时一次主动触达，所以添加后 10 分钟及 20 分钟两个节点可以保存，但第二个可能被频控拦截。

普通 Facebook/IG 自动消息继续限制在可信客户消息后的 24 小时内，并预留 5 分钟。第 2、3 天节点可以配置和计算，但不会绕过这个限制。时间线显示的是预计值和风险提示，不是实际发送承诺。

本轮扩展仅接入本地演练，真实发送保持关闭。即使未来误启旧发送 Worker，新内容组和新时间规则的真实入组也会被拒绝，必须先实现并单独验收逐条提交、失败与未知状态对账。

## 数据与接口

在已有 `SopDefinition.nodes` / 不可变 `SopVersion.config` JSON 内扩展，无需修改现有表结构。

```json
{
  "key": "followup_1",
  "schedule_type": "calendar_day",
  "basis": "customer_added",
  "day_number": 2,
  "time_of_day": "10:00",
  "messages": [
    {"key": "text_1", "content_type": "text", "content": "已审核文字"},
    {"key": "image_1", "content_type": "image", "media_id": 1},
    {"key": "video_1", "content_type": "video", "media_id": 2}
  ]
}
```

新增 `POST /v1/sops/schedule-preview`，使用与调度一致的计算函数。输入节点、模拟添加时间和频控，返回预计时间及窗口/频控/前序冲突。继续要求 Session、CSRF、Origin 和主管/管理员权限。

`POST /v1/media` 保存本地文件；`GET /v1/media/{id}/preview` 返回有权限的预览，视频支持 Range。上传的 HTML/SVG 不作为可执行同源页面返回。

SOP 保存、发布版本、演练和执行明细沿用现有接口。旧单条 `content/media_id` 转为一项内容组读取，不丢失原内容。

## 验证

- 后端覆盖上海日历日、相对时间、前序确认、频控冲突、缺图整组阻断、重启重复执行不追加消息、客户新回复取消、旧数据兼容及视频 Range。
- 浏览器覆盖三种时间模式、文字/图片/视频上传预览、排序、保存回读、发布版本和桌面/手机布局。
- 截图与检查结果：`output/playwright/sop-groups/`。测试视频为 MDN CC0 浏览器样例，仅验证播放链路，不属于旅游原始素材。
- 全程不向真实客户发送、不调用 DeepSeek 改写 SOP 内容。
