# AI 线路接待旅程最终流程

更新时间：2026-09-08

## 1. 系统目标

每条线路独立维护事实、内容组、图片、素材介绍和线路专属说明。系统在客户发言时实时接待，在客户沉默时继续推进同一条旅程；模型负责理解语义与自然表达，代码负责业务裁决、状态流转和发送安全。

## 2. 实时接待

```text
客户消息
-> Webhook 持久化、幂等和人工接管检查
-> 客户理解模型：提取线路候选、问题、档案候选和逐字证据
-> 代码验证候选并合并客户档案
-> 确定性规划器：决定 action、阶段、转人工、单一追问、事实和素材范围
-> 回复生成模型：只负责顾问式客户可见文案
-> 事实验证模型：检查文案是否由允许事实支持
-> 代码校验长度、素材、去重、并发和发送资格
-> 模拟送达或 Chatwoot 发送
```

模型不再一次输出整个系统状态。`action`、`journey_stage`、`lead_action`、`handoff_reason`、缺失档案、定时和素材重发资格均由代码计算。

## 3. 客户可见表达

实时回复和沉默跟进共用 `china2go-taiwan-advisor-voice-v12`。表达规范来自 2026-09-06 冻结的生产聊天快照：289 个会话、6,905 条人工归属公开出站，其中 4,318 条文字、2,587 条素材或附件。客户可见生成节点的完整系统提示和修正提示均使用台湾繁体，不再把大陆客服禁词作为反例喂给模型；禁词由发送前校验器处理：

- 不主动说自己是 AI，也不冒充具体真人。
- 使用自然、简短的繁体中文聊天语气。
- 先回应客户，再说明一个具体价值，最后最多推进一个动作。
- 不使用“当前可接待、资料显示、补充一个重点”等系统腔。
- 人数和日期不是留资的硬性前提；客户说日期不确定后不再追问日期。
- 可用发送完整行程、整理费用、以后随时联系等真实理由自然索取一种联系方式。
- 图片必须说明展示内容、具体特色及对客户的实际价值。
- 中文回复统一使用台湾繁体，全程使用“您”；优先使用“饭店、联络、这边、帮您整理”等台湾服务用语。
- 依语境使用一次“可以呀～、没关系～、不客气～”，不固定以“收到、了解、好的”开场，也不堆叠语气词或表情。
- 客户提出具体问题时第一句直接回答，不得因为主线尚未完成而先谈无关景点、饭店、车辆或追问人数日期。

顾问风格只进入两个客户可见生成节点，不进入客户理解、业务规划和事实验证节点。

## 4. 即时主线与图片

每张正式素材包含：

```text
画面内容
具体特色
客户价值
推荐话术
禁止说法
```

线路确认后，代码会把当前线路所有勾选“确认线路后立即发送”的内容组按页面顺序逐组送达。每组可配置纯文字、纯图片、先文字后图片或先图片后文字，默认逐条间隔 2 秒；每一段提交前都会重新检查客户新消息和发送资格。当前顺序为顾问问候、品牌定位、桃花图、行程图与摘要、希尔顿、车辆；11 日在线路饭店与车辆之间增加絨布旅館。客户直接询问价格、住宿或车辆时，先回答当前问题，再从尚未覆盖的主线继续。

未选择线路时只简要说明 9 日与 11 日核心差别并提供两个选择，不发送线路专属图片。勾选组发送完后，住宿补充、布达拉宫与八廓街、扎基寺和温和承接继续保留在同一主线，由后续客户问题或沉默节点推进。

线路级标准问答只有命中已启用正向例句时才逐字发送，不经过回复生成或事实核验模型改写；来源、长度、风险状态和素材关系在发布时校验。宽泛主题、多问题、健康、实时团况和转人工场景不会硬套标准回答。

## 5. 转人工

代码先验证条件并完成标签、接管状态和任务创建，再生成客户回复。大团、已留资和主动要求真人使用短暂双标签顺序：

```text
创建人工任务并停止其它 AI/SOP
-> 添加“人工接管”，暂时保留 ai
-> 仅当前终止任务发送等待说明和最多一组审核素材
-> 无论发送成功或失败都立即移除 ai
```

`ai` 移除失败时保留“人工接管”阻断并告警，不能恢复普通 AI 接待。

- 当前大团阈值：明确同行人数达到 `8` 人。
- 大团、已留资或客户要求真人：回复“請稍等一下，我這邊幫您安排專人旅遊顧問接著服務”，并可继续提供一项已审核的行程或饭店内容，避免客户空等。
- 投诉、退款和合同争议：只做服务承接，不夹带营销素材。
- 转人工后停止普通 AI 与沉默旅程。

## 6. 沉默跟进

```text
AI 成功回复并确定旅程
-> 绑定该线路当前正式 SOP
-> 客户回复则立即取消旧轮次
-> 节点到期后先执行发送门禁与频控
-> 代码从未覆盖内容和未发送素材中规划一个目标
-> 沉默生成模型按顾问风格生成一条自然消息
-> 事实、重复和素材校验
-> 模拟送达或真实发送
```

当前演练节奏为相对间隔 `1 / 3 / 5 / 10 / 30 / 60` 分钟。沉默消息不催问“看了吗、满意吗、怎么没回复”，而是补充一项新价值；与家人讨论时提供方便转发的摘要；已索取联系方式时说明留下联系方式能获得的具体帮助。

## 7. 配置与安全边界

- 线路管理：线路事实、内容组、线路说明、图片及图片介绍、线路版本。
- AI 接待策略：全局语气、回复上限、留资偏好、沉默节奏和业务规则。
- 系统保护：全局发送开关、渠道窗口、人工优先、幂等、去重、并发和演练隔离。
- AI 演练场：运行生产同一决策链，但消息、任务和素材送达全部写入沙盒。

任何真实自动发送都必须满足：

```text
全局发送开启
+ Chatwoot 当前存在精确 ai 标签
+ 没有人工接管、客诉、拒绝联系等阻断
+ 渠道窗口允许
= 才能发送
```

运行范围只允许 `allowlist` 和 `ai_label`。两种模式都必须有精确 `ai` 标签；`allowlist` 还要求会话 ID 位于测试白名单。`all_eligible` 已被删除并会在配置加载时拒绝。Webhook 建任务、模型调用前、文字提交前和每张图片提交前都会重新读取标签与发送资格。全局发送配置缺失时按关闭处理。

当前阶段只开放 AI 演练场。真实客户全局发送总开关保持关闭，初步验收后再单独进行指定账号灰度。
