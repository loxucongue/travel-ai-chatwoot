## 后台到 V3 的生效路径

| 页面 | 配置 | 消费位置及时间 |
|---|---|---|
| 接待策略 | 开场文字、附件、间隔 | `service.add_message` 在该客户首次输入时创建逐条计划，直接发送原文 |
| 接待策略 | 目标、语气、通用原话 | `compile_skills` → 通用 Skill，下次模型调用读取 |
| 接待策略 | 启用线路 | 编译线路目录与 Skill 索引，停用线路不再作为候选 |
| 接待策略 | 留资渠道、所需资料、人工阈值 | 通用 Skill，主模型决定本轮动作 |
| 接待策略 | 沉默间隔、时段、每日上限、正式启用 | V3 定时任务创建与到期执行；到点调用模型判断是否发送 |
| 线路管理 | 完整介绍、场景原话、事实与素材 | 对应线路 Skill；介绍使用当前顺序和间隔创建持久化计划 |
| 官网资料库 | 已启用资料 | `get_service_facts` 工具按需读取 |
| 系统设置 | 总发送、接待范围、标签、人工控制 | 正式渠道接收和每条交付前检查；停止时取消 V3 未发内容 |
| 系统设置 | 顾问通知 | 实际 HandoffTask 与通知发送进程 |

已创建的交付计划保存当时内容；编辑配置影响后续新计划，不在发送途中替换图片或文字。旧 `v2_intervals_minutes` 只在读取历史配置时迁移为唯一 `intervals_minutes`。旧阶段、业务规则和双套 SOP 配置删除。

## 等待与并发

模型池和交付池分开，慢模型不会占住其他会话的发送时钟。默认模型并发 4，可通过 `LIVE_REPLY_CONCURRENCY` 调整到 1–8；正式与演练各有独立池。领取任务检查会话 generation/revision；客户插话不会被旧模型输出清空。介绍完成与问题分类交错时仍保留问题。

模型失败有有限重试，问题保留；演练显示重试入口，正式接待建立人工任务。外部发送结果未知时不会重复提交。这些是任务与发送一致性处理，不修改模型最终话术。

## 验证

工程回归覆盖配置保存与 Skill 编译、配置开场与媒体、逐条交付、期间问题、取消/改线/交接、真实发送适配、并发、失败恢复、材料与官网资料、账号及渠道控制。

真实模型使用三个独立长对话：9 日三分钟预约、11 日五分钟预约、未选线→比较→选择→完整介绍→住宿顾虑→自然沉默。均使用独立数据库和费用账本，禁止任何客户渠道写入。完整对话、模型输出、费用和实际时间保存在服务器 `output/v3-consolidation-acceptance`。
