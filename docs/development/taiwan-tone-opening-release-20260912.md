# 台灣顧問語氣與開場訊息組

## 變更範圍

- 即時與沉默生成共用柔和台灣顧問規範。三個語氣預設解析為具體繁體描述，不再只傳英文識別碼；營運補充要求保留並傳入兩個生成節點。
- 理解、事實核驗及四個離線分析提示詞轉為繁體；不添加銷售語氣，不改欄位、列舉、判斷權限或客戶逐字證據。舊有儲存狀態 `未确定` 保留相容。
- 健康、退款與客訴採認真有禮語氣。不冒充具體真人；直接詢問身分時仍如實回答。
- 基礎接待改為開場訊息組、AI 回覆語氣、文字與圖片上限；接待目標與其他表達要求收至可展開區域。保留原配置，不清除營運文字。
- 未選行程開場支援 1–10 則文字、排序、刪除、1–30 秒間隔。逐字傳送，最後一則附選項；仍不附行程圖片。每則提交前保留安全門禁。
- 語氣只調整生成內容，不改寫已審核固定回答、主線與開場原文。固定內容需在線路或開場編輯器直接修改。

## 效果測試過程

第一輪 v61：550 項單元回歸通過、2 項跳過；前端構建通過。68 條歷史回放中 66 條通過，20 個演練中 19 個通過；業務連續對話的日期未定檢查未通過。原報告保存在 `output/taiwan-voice-v61-*`，不能當作全部通過的部署依據。

查出的問題：複合詢價超出文字預算；飯店正文引用不完整後觸發安全重寫及素材暫停；日期未定時生成正文與已規劃的留資邀請重複，還要求之後告知日期。

v62：縮短正文目標預算，要求逐句選擇實際支持的引用；日期未定且沒有待回答事實時直接使用已規劃的完整留資問句，不再生成重複前言。沒有放寬事實核驗或發送上限。

核驗 v10 補充文字事實與已審核素材敘事的聯合檢查，修正把素材已明示的客房、紅框設備位置誤判為無依據的情形。仍不得從照片推導醫療效果或每晚飯店保證。

最終歷史回放首輪 65/68，3 條為被攔截的模型輸出失敗；只對這 3 條各進行一次額外復測。首輪保存在 `output/taiwan-voice-final-history/first-pass-results.jsonl`。不把合併復測通過率當作首次成功率，更不代表任意問題均能成功回答。

桌面及手機瀏覽器已驗證新增、排序、刪除、語氣選擇及保存資料；該 UI 測試使用模擬 API，後端契約與實際模型演練另行測試。
