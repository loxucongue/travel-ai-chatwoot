# AI 接待 V2：效果优先的修复与验收方案

日期：2026-09-17。状态：第一批代码优化已完成，效果评测与上线验收待执行。上次生产核查时 297 个会话均为 V1，真实发送关闭；本次未重新核查生产状态。

## 第一批实施进度

- 明确拒绝联系在 webhook 接入和任务执行前识别，持久关闭会话自动化并取消回复、沉默任务；即使全局发送未开启，收到的拒绝也会记录。确认文案暂不自动发送。
- V2 自由生成的回复统一进入事实核验，取消按意图和关键词判断的低风险绕过。
- 会话版本切换改用条件更新；实时回复和沉默任务在执行前检查会话引擎与发布号。Skill 内容进入发布号摘要；旧发布包不可用时停止执行，不静默使用新版。
- 事实工具增加中文主题映射；少量完整的“考虑一下”表达使用固定简短承接，无需模型调用。V2 沉默决策为 `skip` 时终止当前跟进轮次。
- 后端全量测试：1111 passed、4 skipped；最终两项补充测试单独通过。尚未完成不少于 100 轮同题评测、人工盲评、并发切换压力测试及线上试点。因此不能宣称回复质量或 p50/p95 耗时已达目标。

## 目标与边界

首要目标是让 V2 在真实客服任务上更会回答：先解决当前问题、少重复、少无谓追问、知道何时交接与何时不触达。速度必须按最终可发送结果计，不以模型首字速度替代。V2 的所有改进先在隔离演练与只读评测中验证；四项上线风险修复和回归通过之前，不启用真实 V2 会话。

对照使用同一模型、同一批准知识快照、同一历史上下文和相近负载；V1/V2 各自状态隔离。样本以已有 68 条历史问题为核心，补足至少 32 个多轮、拒绝、人工、沉默和竞争事件，总计不少于 100 轮。每条保存最终答复、事实引用、模型调用次数、总耗时、错误与人工盲评结果。

## 阶段 A：先建立效果基线，再迭代回复

1. **同题回放与评分。** 把真实问题和连续对话拆为单轮与旅程两层评测；人工盲评“是否回答当前问题、事实正确、是否重复、追问时机、留资时机、人工交接是否合理、语气”。独立记录沉默事件的发送、延后、停止及理由。自动规则只做风险筛查，不代替人工质量分。
2. **先修最影响感受的三类行为。** “考虑一下”只简短承接；连续追问只补新信息；线路比较只围绕客户关心的差异。把这三类做成有预期行为的多轮回归，不继续在主提示词上累加零散例外。
3. **改善知识工具。** 给价格、供氧、住宿、交通、费用包含/不含等主题建立稳定的中文主题映射；返回经过版本和适用范围过滤的事实，记录工具命中率。比较两条线路时保证相关两边事实都可得，缺资料时说明未知并交人工核对。
4. **压缩完成时间。** 简短承接使用严格限定的确定性路径；事实型问题仍保留验证。先测清模型、工具、核验和排队各自耗时，再优化工具轮次、上下文长度与验证范围。不能以放开事实核验换速度。

阶段 A 完成条件：至少 100 轮同条件对照，人工盲评当前问题覆盖率至少 95%；严重错误为零；重复解释与不合时宜留资相对 V1 明确下降。普通问答最终可发送 p50 至少不慢于 V1，p95 不明显恶化；“快 30%”作为优化目标，未达到则如实报告，不作为已实现能力。

## 阶段 B：修四项上线风险

| 风险 | 修复动作 | 必须证明的行为 |
| --- | --- | --- |
| 拒绝联系仍可进入后续自动流程 | 在模型调用前识别明确拒绝；同一事务写入持久 opt-out/停止状态并取消当前沉默任务。确认回复作为独立可选动作，不改变停止状态。实时回复和沉默执行前再次查停止状态。 | 客户说“不要再联系”后最多得到一条确认，不再产生任何主动任务；重试、重启、切回 V1 均保持停止。 |
| 版本切换与任务领取竞态 | 会话版本采用带 expected_version 的条件更新；任务领取和最终发送前同时核对会话绑定修订号与任务引擎版本。切换只在无发送中或结果不确定任务时完成；排队任务原子取消。 | 并发领取/切换只允许一种结果；旧任务在切换成功后无法提交或发送，发送结果不确定时切换被拒绝。 |
| 发布号仅被记录 | 任务记录发布号及 Skill 摘要；执行时校验发布号与可用不可变包一致。旧包保留到相关任务完成；包缺失时暂停并交人工，不静默改用当前包。 | 发布新 Skill 后旧任务仍用旧包或明确停止；日志可追溯实际使用的包摘要。 |
| 某些回复绕过事实核验 | 将“低风险承接”限定为确定性模板，不由模型自由填写业务承诺；其余自由生成文本进行事实/承诺检查。对“已预订、保证、退款、优惠、医疗安全”等承诺建负面测试。 | 无事实引用也不能说出未经批准的服务承诺；事实性和高风险回复必须经过核验。 |

阶段 B 完成条件：每项同时有单元、API/worker 集成与竞争/重启测试；V1 全量回归保持通过；生产保护状态与发送范围不变。

## 阶段 C：多轮旅程与沉默唤醒验收

用隔离演练复现“新客询问 → 选择线路 → 细节追问 → 考虑 → 沉默 → 再次咨询/交接/停止”。核对原始消息、客户事实证据、已送达内容和每次候选触达。沉默 30 分钟与 24 小时只是候选评估时间；应能选择发送有新价值的信息、延后或停止。客户新消息、人工介入、拒绝联系、资料待核实必须使旧候选失效。

至少覆盖：新客未选线路、两线比较、价格和费用边界、健康顾虑、已提供联系方式、8 人定制、与家人讨论、明确拒绝、人工回复、发送中版本切换、部分素材已送达及模型超时。每条旅程检查是否多发、漏答、重复追问和错误唤醒。

## 阶段 D：小范围试点门槛

只有 A–C 均通过，才形成具体的试点会话清单、时间窗口、人工值守与回退条件。试点先保持显式会话绑定，不能改变全局默认 V1；按日观察回复质量、送达耗时、人工接管、投诉与 opt-out。任何严重事实错误、拒绝后触达、双发或越权发送立即暂停 V2 新任务并核对在途任务。

## 一个新客旅程示例（目标行为）

1. 客户：“想去看桃花，9 天和 11 天差在哪？”系统记录原话并固定该会话的引擎版本。V2 加载线路选择 Skill，读取两条线路的批准事实，先比较与客户决策相关的差异，再问至多一个确实会改变建议的问题。若事实不足，不能编造价格或团期。
2. 客户：“我不想太赶，9 天多少钱？”会话已有偏好不再追问。V2 加载 9 日线路 Skill，读取当前批准价格和费用边界，直接回答价格；必要时说明单房差或未包含项，避免把完整行程重发一遍。
3. 客户：“氧气需要自己带吗？”V2 读取医疗与供氧事实，只补充这一问题的答案，不再复述报价；不保证绝对不会高反。
4. 客户：“我先跟家人讨论。”V2 简短承接，不索取联系方式。系统只建立受频率限制的沉默候选任务；到期前若客户再发消息，旧候选取消。
5. 若客户仍未回复，到期后重新检查权限、人工状态、拒绝状态、最近消息和已送达内容。V2 加载沉默 Skill，决定延后、停止，或只发送一条尚未提供且有助决策的短信息。到期不等于必发。
6. 客户后来主动说“请顾问加我微信……”时，V2 承接客户指定渠道并交给人工，停止自动销售跟进；客户若说“不要再联系”，持久停止主动触达，可选发一条确认，但绝不继续唤醒。

此示例描述目标行为和现有架构可承载的路径，不代表目前所有环节都通过验收。尤其拒绝联系、版本切换、发布包校验和核验边界必须先按阶段 B 修复。
