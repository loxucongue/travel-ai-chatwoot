# V3 连续接待效果测试与主分析报告

测试日期：2026-09-28。评估对象：台湾语气、顾虑处理、聊天留资、沉默触达。

## 总判断

**当前版本能完成接待、基础答疑和留资动作，但还没有达到整段对话可稳定直接使用的标准。** 主要差距不是模型不会说繁体中文，而是该查资料时未查、已经问过的事继续问、把留资当成回答后固定尾句。普通问题常能答对，连续聊天才暴露这些问题。

沉默部分必须拆开看：没有新信息时能选择不打扰；客户预约的提醒可以实际触发。前者不能证明培育话术优秀，后者也不能替代自然沉默后的兴趣培育验收。

本轮只测试与分析，没有修改线上话术、Skill、模型提示词或业务代码。

## 测试方法与边界

- 使用服务器当前 V3 代码：`reception-v3-8cff9d9dc1d49b19`；真实模型 `deepseek-v4-flash`。
- 从当前数据库只读复制配置、知识和素材到独立数据库，使用和演练场相同的 `reception_v3.service.start/add_message/tick` 链路。未调用客户发送接口，未创建真实顾问通知。
- 八段主对话分别有至少10条连续客户消息，第一条是实际线路名称；另有高意向与住宿顾虑的两个复测会话。这里的“轮”按客户消息计算，不把一组 SOP 的十几条素材冒充十几轮对话。
- 测试者先设定客户身份与目标，阅读实际回复后分批追问；有些关联追问连续排入队列，每次均等上一轮交付完毕。不是八十个独立问题，也不是让模型给自己的文案打分。
- 完整经历配置开场、对应线路介绍、答疑、意向推进。单独检查省略追问、明确纠正、日期未定、拒绝留资和留资后的行为。
- C1—C6 及 R1 保持复制来的沉默配置 `[1,120]`。C7、C8、R2 **仅在测试副本**改为 `[3,5]`，全天允许评估。当前实际配置的 `live_enabled=false`，因此本次不能宣称正式客户渠道已经开启沉默触达。
- `[3,5]` 是依次等待3分钟、再等待5分钟，不是统一在累计第3、5分钟各发一次。另观察累计5分钟时的状态。若第一次决定停止，后续没有模型调用是实际结果，不能写成“第二次调用通过”。
- 全部等待采用真实墙钟时间，没有点击“下一次跟进”、没有跳虚拟时间。另以客户明确预约3分钟、5分钟作为正向发送场景，单独标注。
- 原文里的产品承诺以本轮有效配置和提供给模型的知识作为核对依据；本报告不把历史口径自动覆盖到当前产品，也不代替产品事实的外部审核。
- 语气评价是本轮逐条阅读的判断，尚无台湾业务顾问独立盲评；合成客户的留资不等于真实转化率。

## 最需要处理的问题和原文证据

### 1. 有资料却没查，造成“顾虑没有解决”

C2 客户：“車上有氧氣，那下車看景點的時候呢？”

AI：“下車看景點的時候，珠峰那晚住的絨布旅館房內就有供氧設備……”

这是对象答错。客户明确纠正“我问白天离开车子”，AI 又说“這點資料上沒有寫”，转向顾问和留资。

实际本轮 `website_facts` 中已有 `web.1.4.7.0`，说明5000公尺以上景点的车载氧气和随身氧气安排，并有适用范围限制。该轮没有调用 `get_service_facts`。随后问随团医师时才调用该工具。

**原因有直接证据：**官网事实不直接进入模型动态输入，需要工具读取；模型没有查，就把“线路 Skill 未写”当作“系统没有资料”。应解决工具调用时机与知识可见性，而不是再加一个话术审核模型。

### 2. 已拒绝或暂不回应留资，仍重复索取

C2 客户先说“先不用加好友”，后面问随身氧气、随团医师、9日高反，AI 连续三轮以“方便留一下您的微信或LINE嗎”结束。

C3 前三轮分别在年龄、步行、膝盖问题后索取联系方式。客户不得不说：“先不用一直問聯絡方式，我想先了解清楚。”之后才停止。

这不是“没有主动留资能力”，而是**主动留资过密**，顾虑越多反而越像被催。

通用 Skill 已写“已问过未回应不再索取”，但线路 `contact_request`、`contact_after_read` 的不适用示例为空，原话又是“微信或Line的QR code”。因此“只问一种”“不要重复”的通用规则与显眼的线路原话并不一致。模型 trace 多次自述“只索取一种”，实际文本仍列两个渠道；不能用模型自述作为通过证据。

### 3. 优先原文变成整段复制，漏掉当前具体任务

C6：“兩個人住一間，11日一共多少？含哪些？”

AI 给出每人11,480、单房差、团期和包含项目，却没有算两人的总额。客户后来明确要求“請你算兩個人的團費總額”才得到22,960。R1复测再次遗漏总额。

优先原话本身没有问题，但需要围绕当前问题选段、计算与衔接。此处无需新架构，只需把“每人价格原话”与“客户问总价时的回答方式”写清楚，并用这一对连续追问验收。

### 4. 当前讨论对象与入口线路混在一起

C4 从11日入口进入，已经连续讨论9日预算。客户问“我們兩個能用這個價嗎”，AI又解释成每人11,480。客户必须明确纠正“剛剛是在問9日的價格”。

**已观察到的行为：**上下文里的“这个价”承接错了。入口绑定线路影响当前话题是合理推断，不能把推断当成唯一已证实原因。应让模型区分客户入口线路、正在比较的线路、已经最终选择的线路。

### 5. 没有依据的安抚没有真正解决顾虑

C1 波密洗澡与清洁问题，AI说“這部分不用擔心”，随后又说请顾问确认。

C7 将“波密地区条件有限”扩展为“就沒有這樣的設備規格”，但提供的资料未足以支持该否定结论。

C3 将“两人一房”说成所有住宿浴室均在房间里，并直接允许长辈在车上等，再追加待确认。

这类回答先承诺、后补“确认”，既不能让客户知道到底已知什么，也没有具体解决担忧。应把已知事实与待确认项目分清；“已经请顾问处理”还要与实际动作相符。不能以安心口吻替代信息。

### 6. 台湾语气主要问题是连续聊天的机械感

好的例子：C1 房差“如果先生想自己住一間，就是補單房差人民幣2,600元喔～”；C6指定LINE后的承接简洁清楚。

需要改的不是把所有用词替换一遍，而是：

- 连续重复“我幫您記下來了～”“方便留一下……”与“還有想了解的部分嗎”。
- C5刚说日期没定，下一轮又问“您大概想幾月出發”。
- “VIP航空母車”来自当前线路原话 `vehicle.answer_text`，AI照抄到实际回复。不能只归咎模型台湾语气差，需要清理源话术中的明显错字。
- 原话强调卖点时较长，模型没有始终按当前问题缩短；高反答疑尤为明显。

因此语气评为“部分可直接使用，整体仍需小改”，不宜给出“台湾语气已全部达标”。

## 沉默：实际发生了什么

以下时间均为北京时间，日期2026-09-28。最终实测时间和计量见附录。

- C7：最后承接客户商量的回复在23:21:56；约3分钟后执行 `silence_due`，选择等待并停止后续评估，没有发送消息。累计5分钟以后继续观察也没有重发图片或索取联系方式。
- R2：以相似住宿顾虑复测，最后回复23:22:27；约3分钟后同样不发送并停止后续评估。此结果重复出现。
- C8：在客户说先商量时，当前回复就停止了后续评估；因此累计3分钟、5分钟无消息，也没有第二个沉默模型回合。
- C4：客户明确约定3分钟后提醒讨论9日预算。23:24:13承接，23:27:16实际发送：“剛剛約好來提醒您一下～9日（不上珠峰）兩位同住一間，團費合計大約¥19,960，三月底出發。您和先生討論得如何呢？”没有重新发资料，没有索取联系方式。
- R1：客户明确约定5分钟后提醒提供LINE ID，单独验证5分钟实际发送，最终结果见附录。

**判断：**没有新信息时保持安静是正确行为，不能为凑触达次数强发。与此同时，当前自然沉默样本均未产出值得评价的新价值话术，因此“会继续培育兴趣”仍未得到正向证明。若业务希望波密顾虑后补具体酒店资料，当前首先缺的是可用的具体内容和实际核对结果，不能让模型重复安抚来冒充新价值。

还有一个明确边界：当前正式主动发送开关关闭；这些成功均指隔离演练的真实时间调度与模拟交付，不是Messenger实际送达证明。

## 推荐处理顺序

1. **先改现有 Skill 和话术数据的冲突。** 留资话术补明确适用/不适用场景，已经问过未回应或已拒绝时不再引用；选择一个渠道，并避免用已发过的完整资料作为新理由。
2. **让“线路里没有”之后真正查官网知识。** 优先调整工具说明与少量关联场景示例；若仍稳定漏查，可把与当轮相关的短事实直接附在上下文，不增加回复后审核调用。
3. **解决原话选段和省略追问。** 总价要计算，房差只答房差；“这个价”跟随当前讨论对象，不凭入口线路覆盖当前问题。
4. **清理源话术。** 修正“航空母車”等明显错字，移除与通用接待要求冲突的重复尾问；保留业务原话的风格，不做全局词替换。
5. **沉默内容缺什么补什么。** 有具体新信息才补，无新信息就停；预约提醒与自然培育分别验收。
6. 按 C2、C4、C5、C6、C7/R2 这些完整对话复测。保留这次失败原文，不能只重测最后一句后宣布整段已改善。

无需再增加多级审核、复杂后台或更多 worker 来处理以上问题。worker 能改变排队等待，不能修正答非所问、选错话术或重复留资。
