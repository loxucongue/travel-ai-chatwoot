## 修复顺序和验证范围

1. 主动拒绝与被动回复分离：拒绝后主动提问、否定拒绝句、拒绝与问题同轮；验证持久状态与任务取消，不只检查确认文字。
2. 合并资料交付与人工待办：PDF＋车照、整套资料＋未知事项、留资＋多附件；比较审核对象、持久计划和实际提交记录，不能只看素材键。
3. 修正错误分类与失败处理：保留真实人工任务、准确原因；如补客户承接，验证新消息打断、渠道窗口和重复执行。
4. 修正时间来源：隔天新消息、同轮合并消息、跨时区、真正超窗的预约。
5. 修正文案归一化、必要条件指令和渠道枚举；同时验证 V1 兼容性与 V2 原有语气要求。
6. 最后补真实调用统计、最终交付追踪与有效版本展示，再进行少量模型对照。模型测试与真实渠道、设备收件验收分别记录。

前四项不应通过扩大提示词或更换模型掩盖。预计这些修复会提高执行一致性，但在实测前不能承诺自然度或耗时提高多少。
