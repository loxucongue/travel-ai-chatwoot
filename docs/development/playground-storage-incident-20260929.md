# 演练创建失败与 V3 优化发布

## 故障原因

2026-09-29，演练页面创建新客户显示 `Failed to fetch`。服务器 API 日志在创建会话提交事务时记录 `sqlite3.OperationalError: database or disk is full`；根分区 49G、使用率 100%，可用空间为 0。API、演练、正式回复和 nginx 服务均在运行，因此重启 Worker 不能解决问题。

两份旧 V2 发布的预检目录各复制了完整历史备份，重复占用约 12 GiB：

- `releases/v2-business-final-20260921T100756Z/check/data/backups`
- `releases/v2-trust-final-20260921T114147Z/check/data/backups`

对照 `/opt/china2go-ai/data/backups` 原件逐个检查相对路径、文件大小及 SHA-256 后，仅删除 218 个一致的重复文件，共释放 12,895,805,440 字节。原始备份、当前业务库和当前发布保留。核对记录保存在本地忽略目录 `output/disk-duplicate-cleanup-20260929.jsonl`。

## 修复

- 数据库运行错误在 API 内返回结构化错误，磁盘不足为 HTTP 507，其他数据库运行错误为 503；跨域响应正常包含 CORS 头，网页可以显示具体原因。
- 演练切换客户或新建时清除上一操作的错误状态，避免旧错误留在新客户页面。
- 发布预检只复制数据库和线路覆盖配置，不复制上传素材和备份目录；预检和发布备份前检查剩余空间，上传包解压后删除临时压缩包。
- 同步发布此前保留的 V3 第二轮优化，包括官网事实与两条线路事实可见、总价和差价解释、单渠道留资表达及话术使用说明保存。未加入第三轮已撤回实验。

最新优化的效果依据和未解决问题仍以 `v3-effect-iterations-20260929.md` 为准。部署不等于台湾语气、留资时机和沉默培育全部达标。
