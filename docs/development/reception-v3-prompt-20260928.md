# V3 系统提示词与 Skill 职责修正

此前系统提示词混合接待规则、输出协议和旧配置；通用原话的适用场景、线路原话的部分条件没有传给模型。发送层还会在 `asset_keys=[]` 时附上原话图片。这些会造成正文选对了、实际交付仍不符合意图。

## 改动

- `prompt.py` 提供稳定的身份、工具加载和 JSON 执行协议。完整接待方法与对话示例放在 Skill，移除 Skill 中重复的整份输出协议。
- 通用场景的 `scenario`、线路的 `ai_guidance`、`negative_examples`、人数条件、主题和使用说明随当前配置加载，不新增配置副本。
- 只把 V3 实际使用的表达、留资和沉默设置传给模型；不再传旧版按回答主题数量触发留资等参数。开场和整套 SOP 仍由交付层按配置执行。
- 场景原话允许按问题选段：适合全文才引用原话，否则模型输出最终文字。区分首次介绍、介绍完成和后续追问，不把原话里的“先发介绍”带进已经介绍完的答疑。
- 图片只取模型明确选择的 `asset_keys`。引用原话不隐式附图；整套介绍仍使用配置中的图文顺序。
- 增补连续对话示例：介绍期间的机票问题与人数、房差追问、未回应的留资、住宿顾虑、普通沉默、微信偏好与实际号码。
- 初轮人工阅读发现住宿例外被缩窄、把日期补充当成查余位。补充具体正反例后复测。没有增加模型审核、关键词分类、回复裁剪或前端页面。

## 验证方法

最终候选定向回归 52 项通过：V3 服务、Skill 工具加载、演练 Worker 和旅程接口。1 条现有 Starlette 弃用警告。此次没有重跑整个后端或前端构建，修改限于独立 V3 与验收脚本。

真实模型使用服务端当前 Flash 模型、独立数据库和预算账本，仅允许模型 HTTP，禁止渠道写入。9 日旅程覆盖整套介绍、插话、尾问、人数日期、房差、供氧、真实三分钟预约和交接；11 日旅程从泛咨询、比较到选线，再进入介绍、房差、住宿顾虑、自然沉默和微信交接。

11 日的自然沉默仅在复制出的测试配置内设置 `[3,5]`，实际等待三分钟再等待五分钟；不是让客户要求三分钟后联系，也不是把时间快进后宣称真实等待。没有新价值而选择等待/停止是可接受结果；实际触发次数和文案另行记录。

原始证据保留在 `output/v3-prompt/` 和服务器 `/opt/china2go-ai/output/v3-prompt-20260928/`，包括初轮失败与最终复测，不用最终结果覆盖初轮。

## 边界

后台完整 SOP 的第一段仍配置着自我介绍，因此可能与全局开场重复。该段是固定配置原文，不由模型生成；此次没有通过隐藏的跳过/裁剪逻辑修改它，也没有修改共享产品配置影响正式 V2。要消除这项重复，应在后台将该段改为线路承接语或移除重复问候。

原话中的产品事实仍采用当前官网线路资料。本轮改善的是资料使用、上下文选择和交付一致性，不代表所有原始业务承诺经过独立核实。

V3 仍用于演练；正式客户保持 V2。本轮不等于正式渠道发送、真实顾问交接和设备通知验收。
