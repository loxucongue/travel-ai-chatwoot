# 连续对话与沉默触达效果验收方案

状态：已于2026-09-27执行；当前版本未通过业务验收。见[实际结果](../development/continuous-conversation-effect-results-20260927.md)。

## 业务效果

1. 每个新客户首次消息执行已配置开场，文字、附件和顺序一致；后续消息不重复开场。演练每个会话视为一个独立客户。
2. 广告入口已表达具体线路时直接承接；未知线路才匹配。已说人数不重复问，未知人数按线路话术询问，不要求先填完日期和预算才介绍。
3. 确认线路后按真实配置依次完成整套介绍，使用正确的行程图、景点、住宿、车辆素材和间隔，不自行插入房间照片或遗漏内容。
4. 完整介绍期间普通问题进入队列；整套介绍结束后集中答复，不能丢失、重复回答或被沉默消息插队。停止、明确改线和人工接管立即处理。
5. 命中场景话术优先保留原文，只调整必要的称呼、衔接及客户已给出的条件；无话术时用当前线路事实与官网知识回答，不编造事实。
6. 多轮能理解省略追问、人数更正、线路比较与明确切换，延续已有客户资料，不把历史信息当成本轮新要求。
7. 回复自然、台湾用词合适，答全复合问题；不出现内部编码、审核口吻、无关长篇说明或机械重复追问。
8. 合适时主动索取一种联系方式，并承接客户偏好；有明确意向却持续不推进，也属于失败。拒绝单个渠道后不强行换渠道索取。
9. 收到有效联系方式或明确要求顾问时形成真实人工任务，停止后续自动销售与沉默触达；不能只在文字里说已经交接。
10. 沉默时按配置和当前兴趣提供相关、未重复的价值；不因为到时间就机械发消息。拒绝主动联系后停止主动触达，但允许回答后来主动提问。

## 测试执行条件

- 复制当前发布的两条线路、公共接待配置、通用知识和实际素材到隔离测试环境；记录代码、模型、配置、知识版本及素材校验值。
- 主轮次使用真实模型和完整运行/交付链路，每位客户维持同一会话、记忆、资料记录及问题队列。禁止逐句重建会话、手工补状态或以预设答案替代模型。
- 只隔离客户渠道写入，不修改线上开关。演练实际提交的文字与附件作为验收对象，不能只看模型草稿或工具返回。
- 使用真实图片/PDF并人工核对实际画面，不能用占位图通过顺序测试。
- 客户有预先固定的人设和目标，后续发言根据实际答复承接；保留完整实际输入。主流程使用脚本预定关键情节，不另用一个模型任意编排客户并自动宣布合格。
- 记录真实 HTTP 请求次数、token、费用；先跑一个完整旅程估算整批消耗，再小批执行。先不重复旧的数百条单轮测试。

## 六条主体旅程

每条约 8–15 次有实质内容的客户发言；SOP 自动发送的多条消息不计为客户轮次。因拒绝/交接应结束时立即结束，不为凑轮数继续。

| 旅程 | 连续情节 | 重点 |
|---|---|---|
| A：9日广告新客 | 广告线路入口 → 询问人数 → 2位 → SOP期间询问住宿和费用 → 集中答复 → 省略追问 → 改成4位 → 考虑 → 沉默 → 再次提问 → 留资 → 交接 | 主路径、问题队列、资料顺序、人数记忆、主动留资 |
| B：11日广告新客 | 首条已含人数 → 不重复询问 → SOP期间问珠峰住宿和供氧 → 连续追问房间/车外的区别 → 同行长者条件 → 沉默 → 再次咨询 → 留资交接 | 11日专属事实、问法衔接、不能凭天数推断更轻松 |
| C：无线路入口 | 按配置开场 → 表达看桃花但顾虑体力 → 比较两条线路 → 选线 → 人数确认 → 完整介绍 → 住宿追问 → 表示考虑 → 沉默后继续 | 匹配、比较不等于切线、不过早留资 |
| D：更正与改线 | 9日入口 → 人数 → SOP期间比较11日 → 明确改选11日 → 保留人数 → 新线路资料 → 日期更正 → 后续“那晚呢”等追问 → 沉默 | 区分比较与切换、停止旧线路未发内容、不混图/价格 |
| E：弱意向与拒绝 | 完成介绍 → 连续答疑 → 拒绝LINE → 继续答疑 → 与家人商量 → 沉默 → 明确不要主动联系 → 再沉默 → 主动回来提问 | 有分寸、不机械换渠道、拒绝后仍能被动答疑 |
| F：多问题与人工 | 完成介绍 → 同轮询问已知费用和未知实时事项 → 索取图片/PDF → 延续追问 → 主动提供联系方式或要求顾问 → 沉默 | 已知部分答全、资料不丢、具体人工任务、交接后停止 |

额外在 A/D 的介绍中途注入“先别发了”和“请真人接手”两个短分支，验证立即停止；不把短分支冒充完整长对话。

## 沉默时间验收

两个业务时钟分开记录：线路固定介绍的组间隔，以及答复完成后的沉默跟进间隔。每次事件保存最后客户消息时间、最后实际交付时间、任务 due_at 和本次执行时间。

- 每条旅程在合适位置观察 T+1、T+3、T+5 分钟；到期边界另检查到期前与到期后。
- T 的来源写在报告中，按当前实际调度合同计算；客户沉默时长与系统回复结束后时长同时展示，不混为一个数。
- 最近部署核对的 V2 间隔为 [1,120]（后续间隔从上次跟进计算）；执行测试前重新读取配置。因此 3/5 分钟是观察点，不代表都必须新增触达。还要核对线路 SOP 自己的调度。
- 默认配置下没有到期任务且不应触达时，保持安静才是通过；有应发送的任务却没有执行，则是失败。
- 独立复制配置分别测试首次 3 分钟、首次 5 分钟触达，以验证配置真正生效。只修改隔离测试副本，并在报告标注，不能冒充线上配置。
- 对两条线路各至少一次按真实墙钟等待超过 5 分钟，后台自动调度，禁止点击“下一次触达”。其余分支可逐步推进虚拟时钟，但必须标记为加速验证，不能跳过中间任务。
- 检查三类结果：应该发且发对、应该等待且没有发、不该再发且已停止。
- 在等待到期前客户又回复，旧沉默任务应取消；检查恰好到期时的新消息、人工接管、拒绝状态，避免旧内容穿插。
- 每条实际触达检查：是否对应最后顾虑、是否有新价值、是否重复此前正文/附件、是否过早索取联系方式、是否使用最新人数与线路。

## 人工阅读与结果记录

我逐条阅读最终可见文本并查看实际图片，按整段对话评判。程序只辅助检查时间、附件顺序、队列、联系方式状态和人工任务，不能用关键词命中或模型自评代替阅读。

每条记录包括：相对时间、客户原文、AI实际全部消息/附件、命中的配置/话术/事实来源、应有行为、实际行为、判定与理由。另列首条有用答复和完整答复耗时，不把排队中的客户问题等待时间掩盖掉。

文案评判分为：可直接发送、需要小改、需要重写。上下文衔接、台湾表达、问题覆盖、重复/推脱、留资分寸单独写明依据。

硬性失败包括：开场不一致、错线/错图、漏发介绍、问答丢失、改线后旧资料继续发、关键事实错误、重复问已知人数、拒绝后继续主动联系、留资后仍继续销售、只口头转人工却没有任务。

首轮保留全部原始失败。修复后重跑失败旅程从开始到结束，再复测另一条线路的相邻边界；不只挑失败的单句重试。最终报告列出通过、失败、未覆盖及重复验证结果，不将跳过项算通过。

## 最终交付

1. 六份完整客户时间线（含所有客户消息、AI消息、图片和沉默事件）。
2. 单列 3/5 分钟观察、配置触发测试及真实等待结果。
3. 按业务效果逐项给出达标/部分达标/未达标和证据。
4. 问题清单、修复与复测记录，以及模型调用/费用统计。

本方案只证明本轮样本与所用版本表现，不声称线上留资转化率已提升；演练提交结果也不等于真实客户设备收到附件。
