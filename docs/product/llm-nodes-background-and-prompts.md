# 大模型节点背景与提示词说明

更新日期：2026-09-12

本文件解释架构背景；当前完整提示词以 `llm-node-prompts-current.md` 为准。
2026-09-12 的业务复验与部署记录见 `../development/business-doc-optimization-20260912.md`。
首轮延期问句只在实际送达后登记为已问，不能随首条正文提前登记；后续沉默规划读取同一份记录。

## 当前目标

系统负责接待 Facebook / Instagram 进入 Chatwoot 的台湾客户。客户可见内容应像 China2Go 旅遊顧問在聊天：使用台湾自然繁体、短句、礼貌但不僵硬，先回应问题，再提供具体价值，最后最多推进一个动作。

系统平时不主动提及 AI、机器人、模型或自动化，对外以“China2Go旅遊顧問”或“China2Go這邊”承接，也不虚构顾问姓名、年资或亲身经历。客户直接询问是否为机器人或真人时，才如实说明这里使用自动接待协助，并可立即安排真人顾问。

## 实时接待架构

```text
代码发送门禁
-> 客户理解模型
-> 代码业务规划器
-> 三选一：逐字标准回答 / 确定性系统话术 / 回复生成模型
-> 生成模型路径执行事实核验；逐字标准回答保持原文
-> 代码最终校验
-> 发送与旅程状态提交
```

职责边界：

- 客户理解模型只提取线路、问题、人数、日期、联系方式、语义信号和逐字证据。
- 代码规划器决定最终动作、线路、阶段、8 人大团转人工、留资、唯一追问、允许事实和允许素材。
- 逐字标准回答只有在当前线路的已启用例句明确命中时使用，正文不经过生成或事实核验模型改写。
- 普通回复模型只把代码已经决定的业务计划表达成台湾顾问话术。
- 事实核验模型只检查具体说法是否被允许事实或素材叙事支持。
- 发送时间、标签、白名单、人工接管、渠道窗口、频控、幂等和素材去重全部由代码控制。

## 线路旅程架构

客户确认线路后，系统读取该线路的同一条 `content_sequence`：

```text
先发送所有勾选“确认线路后立即发送”的内容组
-> 按页面顺序逐条发送审核图文，内容组决定图文先后，默认间隔 2 秒
-> 未勾选内容保留给后续客户对话或沉默节点
-> 客户沉默时继续选择下一项尚未覆盖内容
-> 没有新内容时 no_action，不为了凑次数硬发
```

当前 9 日线路即时发送 4 组：行程总览、桃花亮点、饭店与房内设备、车辆与车内设备。

当前 11 日线路即时发送 5 组：行程总览、珠峰絨布旅館、桃花亮点、饭店与房内设备、车辆与车内设备。

随后还可按沉默时间节点继续发送：住宿补充、布达拉宫与八廓街、扎基寺、温和承接。客户一回复，旧沉默轮次立即停止，重新进入实时接待。

## 台湾顾问表达来源

表达规范来自 2026-09-06 冻结的生产 Chatwoot 公开聊天：289 个会话、6,905 条人工归属出站，其中 4,318 条文字。原话与分析位于：

- `output/analytics/human-advisor-verbatim-20260906.md`
- `output/analytics/human-advisor-style-summary-20260906.md`
- `output/analytics/human-sop-language-analysis-20260906.md`

只学习表达节奏，不把历史顾问说过的价格、花期、余位、供氧效果或承诺自动当作事实。

客户可见表达固定要求：

- 使用台湾自然繁体及“饭店、联络、行程、帮您整理、这边”等台湾服务用语。
- 不使用“酒店、线路、对接、匹配方案、出行方案、专项顾问”等大陆客服词。
- 不固定以“收到、了解、好的”开头，不使用“资料显示、当前可接待、仅供参考”等系统腔。
- 简单回复通常为 25 至 80 个中文字；较长回复只用于同时回答多项已经审核的事实。
- “可以、没关系、好的、喔、呀、～”可以依语境偶尔使用，但同一则最多一种柔和提示，也不能连续多轮复用同一开场或收尾。
- 场景开头要变化：可以直接回答、先说线路差异、从图片用途开始，或先接住客户顾虑；不能靠堆叠语气词制造台湾感。
- 图片说明至少说清发的是什么，并自然说明画面重点或用途；不得延伸医疗、安全、花期、余位或保证。
- 客户说日期不确定后，不再追问日期；有足够价值后可用“发送完整行程、以后随时联络”自然索取 LINE、微信或 Email。
- 沉默跟进不使用“看了吗、满意吗、怎么没回复”等纯催问。
- 客户问冷暖、价格、饭店或车辆等具体问题时，第一句必须直接回答；未完成主线只能在回答后继续，不能抢占客户问题。

线路包发布时会检查运营编写的客户文案。官网逐字标准回答保持官网原文，不因词汇转换被静默改写；生成式回复和运营新增内容仍执行台湾客户用语检查。

## 线路级逐字标准回答

标准回答属于线路产品配置，不属于全局提示词。运营页面每条只显示一份客户实际收到的内容：

```text
名称、单一生效状态
正向例句、排除例句
逐字回答正文
允许图片、对应线路资料
只读来源位置
```

匹配规则：

1. 必须先由代码确认当前线路。
2. 只能使用状态为 `active`（页面显示“已启用”）的回答。
3. 当前客户消息必须命中该回答的正向例句；只识别到宽泛主题不够。
4. 排除例句、多个问题、转人工、健康、实时团况、线路比较等场景不会强行使用固定回答。
5. 命中后正文 100% 使用已发布文字，回复生成模型不会改写。
6. 官网原话在发布时完成来源和风险状态校验；命中后不再调用模型改写或核验，确保逐字一致。

当前从网站冻结快照导入：9 日 21 条、11 日 22 条。其中 9 日启用 12 条，11 日启用 13 条；各有 9 条风险内容保留为待审核，包括无购物赔偿、年龄政策、孩童高原适宜性、饭店氧浓度、车辆年份以及包含这些说法的整段用车原话。

因此可以保证的是：**命中已审核例句后的输出文字 100% 不被改写**。不能诚实承诺任意自然语言问题都 100% 自动分类正确；未明确命中时必须回到受控生成或人工，不用错误固定答案换取表面命中率。

## 素材事实合同

每张正式素材包含：

```json
{
  "what_it_shows": "图片展示什么",
  "feature_points": ["可以介绍的具体特色"],
  "customer_value": "对客户的实际价值",
  "recommended_caption": "推荐发送话术",
  "avoid_claims": ["禁止延伸的承诺"]
}
```

回复生成读取前四项；事实核验也读取同一叙事。`avoid_claims` 只用于禁止延伸，不能作为支持证据。


文档不包含密钥、客户聊天、联系方式或图片二进制。内部理解、规划和事实核验保持客观；台湾销售表达只进入客户可见生成节点，避免话术风格干扰人数、线路、规则和事实判断。

## 发布门槛

客户可见话术、固定回答或主线变更必须完成：后端全量回归、68 条真实历史回放、11 个边界场景、12 个 AI 演练场客户会话、沉默节点推进、前端构建和浏览器检查。部署期间真实发送总开关保持关闭，部署前后真实出站数量必须一致。

本次台湾顾问表达验收结果：严格语气基准 `17/17`，AI 演练场完整客户会话 `12/12`（隔离评估会话 `#481–#492`），真实历史问题回放 `68/68`。测试同时检查台湾用词、模板开场占比、语气词密度、图片说明、日期不确定、沉默跟进、7/8 人分界、转人工等待文案和季节冷暖直接回答。
