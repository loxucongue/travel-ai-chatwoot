## 目标与范围

验证同一个客户从广告线路进入、人数承接、完整介绍、关联答疑，到首次留资、渠道选择、人工交接或沉默跟进的实际体验。重点是台湾语气、顾虑解答、留资分寸和沉默内容。工程测试数量不代替效果评价。

前轮基线见 `docs/development/v3-contact-reception-release-20260929.md`。前轮仍有普通回答偏长、重复承接、少量地域术语，以及沉默重述旧事实的问题。最终少量成功样本不能证明所有场景都已稳定。

执行前从服务器读取实际代码发布号、模型、Skill、线路资料、公共配置和开场附件；不能仅凭旧报告断言版本。后续同批不改配置。使用当前指定密钥，但测试材料和报告不保存密钥。

## 方法：真实连续对话，客户有固定目标

- 8条主场景，每条通常6–10轮客户消息；另4条未用于调优的新表达场景，每条4–8轮。提前交接或明确结束就停止，不为了凑轮次继续制造对话。
- 一个测试会话就是一个客户。以9日/11日线路名称作为第一句话；另含一个未带线路的入口。完整走一次开场与介绍，不从中间伪造“介绍已完成”。
- 客户有预先固定的需求、已知信息、留资意愿和拒绝条件。下一句话根据实际上一条回答选择：答全就推进、漏答就追问、邀错渠道就纠正；不在AI已经问完或交接后继续机械投喂题单。
- 案例中的客户话只包含自然表达，不写“请遵守Skill”“现在应该问LINE”等答案提示。普通沉默客户不说“你来唤醒我”；只有预约场景明确提出提醒。
- 介绍中插入普通问题，核对整套介绍发完后集中处理。停止、明确改线、要真人另作立即处理检查。记录客户发言到最终回答的等待，而非只记录模型请求时间。
- 逐轮保存原始决策、实际显示文字、图片顺序、客户资料、交接与计时。失败后的自动重试也保留；成功重试不能抹掉一次故障。
- 不让另一个模型同时扮演客户又为自己的对话打分。由测试执行者按客户档案推进、逐条阅读并给出证据；台湾自然度的最终认可是业务顾问复核，不冒称完成了顾问盲评。

## 4条新表达验收场景

在第一轮开始前冻结题库，验收前不拿其模型回复改Prompt或Skill。覆盖：

1. 换一种说法提供四人信息，并更正人数一次；不使用固定的“4位”。
2. 客户说“传信箱就好”，下一轮只发邮箱，不重复标注渠道。
3. 一句话同时问两个顾虑，然后用省略句追问其中一个，要求简短。
4. 首次邀请被忽略、出现新月份问题；稍后明确拒绝主动联系，再主动回来咨询。

每条仍是关联对话。保留题库版本和内容哈希。若新场景发现失败，它就转成回归案例；修复后不能还把同一条称为未见过的验收题，需要补一条新的变体。

## 沉默怎么验收

### 三种结果分别计分

| 类别 | 条件 | 合格结果 |
|---|---|---|
| 必须发 | 客户明确约定3/5分钟提醒，时间到且没有取消、拒绝或转人工 | 按约定交付那件事；不提前、不漏掉，不附带另一个留资问题 |
| 应推进但不指定哪一句 | 尚未问过影响选线的关键需求，或有明确适合的首次邀请机会，客户未拒绝 | 两个观察节点内至少一次有用途的澄清/邀请/新信息；不能连续wait后只说“没新图片” |
| 应停止或等待 | 已问过的问题和邀请均未回应，现有内容已经回答完 | 不换句话重发；不因没有触达就判失败 |
| 必须不发 | 已拒绝主动联系、已人工接管，或客户在到期前新发消息取代旧触达 | 零过期主动消息；新问题照常按接待状态处理 |

“应推进”标签需在对应观察节点之前根据实际历史记录：明确写出尚可帮助的一件事。若此前模型已合理完成该动作，则更新为等待类，不能为了通过测试强迫重复。不能让模型在所有测试里一直wait，也不能以消息数越多越好。

### 时间定义

- 普通沉默：最后一条客户可见回复结束后开始计时，3分钟到首次评估；本轮最后交付或无交付评估结束后，再等5分钟。因此第二节点约在总计8分钟后，加上模型/交付耗时，不是客户最后消息后的第5分钟。
- 单独的预约5分钟：从该预约确认回复完成算起5分钟，只提醒一次。另测一次客户到期前取消，确保不再提醒。
- 到期记录计划时间、实际启动、首条有用文字和本轮完成四个时间。模型已启动但未输出不算消息送达。
- 使用真实时间，不点“测试下一次跟进”替代计时。固定间隔的等待误差先单独记录；建议触达完成在计划到期后30秒内，超出就分析调度/模型耗时，不把它混进话术评分。
- 在受控样本中，于到期前约10秒发送一个新问题，观察旧触达是否取消。安排在A6或A7的复验分支，不中断主样本的完整3+5观察。

## 评分：每个判断都附上下文证据

每轮标记“可直接发 / 小改 / 重写”，再给整段会话结论。SOP原文只核对忠实交付，另外统计模型自由回答，避免大量固定文本抬高自然度分数。

| 维度 | 可直接发 | 重写或失败例子 |
|---|---|---|
| 台湾语气和原话 | 熟悉台湾咨询场景的自然表达；适用原话主体保留；只改合理称呼/衔接 | 简转繁公文腔、只回几个字、连续同一承接句、把四人原话全部换掉 |
| 顾虑与连续性 | 回答当前真正担心的事；多个问题都处理；必要条件准确；区分可回答与待核实事项 | 漏问、答非所问、重新盘问已知信息、虚构价格/安排、用一大段免责代替回答 |
| 留资 | 在合适机会首次邀请，目的具体；尊重指定渠道；实际地址/ID交接正确 | 有机会始终不问、每轮追索、拒绝后换渠道追问、给邮箱仍索LINE、尚未给资料就暂停接待 |
| 沉默 | 所发内容有可指出的新价值或履行预约；该停时停 | 重发团期/图册、反复问同一问题、无依据新承诺、拒绝后触达、到期预约遗漏 |

建议本轮验收门槛：

- 开场/SOP内容及顺序、实际联系方式保存、交接、明确拒绝后停止，所有适用样本正确。
- 关键事实错误、未经依据的承诺、漏交接、拒绝后主动触达：零未解决项。任何一项不能被平均分抵消。
- 适合首次邀请的样本全部有一次有效邀请；测试客户是否愿意留资是题设，不以“留了多少个邮箱”证明真实转化提升。
- 模型自由回答至少90%初评可直接发，剩余不超过小改；最终语气门槛待业务顾问确认。报告单列尚未复核的数量。
- 若程序重试才成功，体验中发生的延迟与失败仍统计；不能写成该轮一次通过。
- 普通问答暂以首个有用回答P50≤6秒、P95≤15秒作为观察目标，不是既有保证。完整SOP耗时单列，不能把配置的图文间隔当模型慢。

UI与实际正文同时核对，尤其留资邀请、联系方式脱敏和接待状态。若页面错误地隐藏普通“LINE ID”字样，或交接后标签与实际状态不符，单独列为显示问题；不能因此错误判定模型没有留资，也不能忽略运营实际看不懂的情况。

## 执行顺序与费用

1. 冻结当前版本与配置，记录每条资料的事实依据；无模型方式检查隔离和记录能力，确认此前测试进程已结束。
2. 跑8条主场景，最多2个会话同时推进。先完成这轮并阅读全文，再决定改什么，不边看同一批边改配置。
3. 问题按原文缺失、Skill冲突、理解不足、事实来源、发送/界面分开定位。只修有证据的问题，不为每句不喜欢的话加替换规则。
4. 修复后只复测失败案例及相邻边界；四人原话、Email承接、连续沉默三个高风险案例各重复一次。达到预算线就停止，报告未完成项。
5. 冻结候选，再跑4条新表达验收。若仍有关键失败，判未通过，不用重跑直到幸运成功；修复后对该失败另行记录验证。
6. 输出逐轮对照报告：客户目标、前文、实际原文、事实依据、判定、状态/交付、时间。部署只有在后续明确执行优化/发布的任务中处理，本轮仅设计。

此前同一20元预算已保守计入¥11.09668936。本方案不默认重新获得20元：总余量约¥8.90，按18元执行线则最多再用约¥6.90。若执行前发现其他测试消耗，再扣除。

建议在余量内为第一轮预留3元、修复复测2元、新表达验收1.5元，剩余作请求预留余量；这是安排上限，不保证足够完成所有样本。所有工具续轮、思考输出、修复和重试计费；请求前按上界预留，失败无用量保留预留。执行前核对实际模型与计费口径。预算不足时列为未测，不计成功，也不把预算中止判成业务逻辑错误。

使用跨本次测试共享总账，按场景查看用量但避免过低的单场景硬上限反复触发自动重试。费用账本或测试执行器不具备这些能力时，先补齐测试工具，不修改业务回复来绕过费用限制。
