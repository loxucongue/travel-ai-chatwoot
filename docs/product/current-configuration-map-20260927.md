## 2. AI 接待策略：四个分区

保存位置为数据库 `AppSetting.route_reception_config`，接口 `/v1/automation/reception-config`。发布影响后续新决策和新入组，已冻结的交付计划及正在运行的 SOP 轮次不被重新编写。

### 基础接待

| 字段 | 当前值/范围 | 实际作用 |
|---|---|---|
| `reply.opening_items` | 两条文字，见下文；最多十项 | 当前开场主数据。文字、图片、视频组合及顺序直接用于交付 |
| `opening_messages` | 同样两段文字 | 旧多段文本字段；有 opening_items 时由它派生 |
| `opening_message` | 第一条文字 | 旧单段文本兼容字段；不是另一个独立开场 |
| `opening_interval_seconds` | 1 秒，可配置 1–30 秒 | 控制开场条目间隔，不控制后续线路介绍 |
| `goal` | 先回答客户，再自然取得一种有效联系方式 | 进入主 Agent 提示；不是定时/计数触发器 |
| `tone` | friendly_professional | 提供表达偏好：亲切柔和、简短有礼、温柔可亲 |
| `tone_guidance` | 台湾顾问聊天表达要求 | 进入模型提示；不会改写程序直接交付的配置正文 |
| `custom_guidance` | 空 | 全局补充说明，进入模型提示 |
| `max_characters` | 200，可选 80–200 | 开场保存时有长度校验；普通 V2 作为提示约束。不能理解为所有输出均被强制截到 200 字，完整话术介绍也不是一条 200 字回答 |
| `max_images_per_turn` | 2，可选 0–2 | V2 接收此提示，但系统提示还写着普通 material_keys 最多两项；完整介绍走独立多段附件计划。不是所有发送路径统一的图片总数开关 |

当前线上开场原文：

1. `您好～我是China2Go的旅遊顧問luo～很高興認識您！`
2. `您想先了解哪一條行程呢？`

当前开场无图片、无视频。首次客户消息按历史状态判断，不再用“你好”等文本关键词识别；演练会话独立看待。V2 在调用模型前生成配置开场，不调用模型生成这两句话。线路按钮来自启用线路的 `selection_title`，不是开场文本字段。

**仍存在的自动处理：**如果开场最后一项是图片/视频，`opening_messages.delivery_items()` 会自动补固定的选线尾问。最新修复把这条尾问同步到编辑器可见的 opening_items，避免删除图片后尾问跟着消失；但“自动补问句”本身并未删除。因此目前还不能说开场完全没有代码补充。

### 版本记录

接口仍固定返回 `v6.4`，并展示旧的理解、规划、事实审核等节点版本。不是当前 V2 引擎的实际发布号。历史列表来自配置更新审计记录，不是完整可回滚的不可变配置版本；绕过该 API 的运维配置修正也不会自动成为这里的一条“配置版本”。

## 3. 线路管理：七个分区

| 分区 | 配置内容 | 怎样生效 |
|---|---|---|
| 基础信息 | 线路名、按钮标题、关键词、默认入口文本、AI 指导、启停 | 名称/关键词/标题参与选线；默认入口主要供演练/入口构造，不会自动配置 Meta 广告。AI 指导仍进入旧 playbook 数据，当前 V2 提示组装未读取该字段，不能宣称改了必然有效 |
| 价格与档期 | 价格、日期、适用条件等事实 | 编辑 knowledge_facts 的筛选子集；查询工具返回这些事实，不是实时库存系统 |
| 线路资料 | 内容组名称/用途、正文、图片引用、事实引用、交付方式、是否首次介绍 | 编译成线路介绍和可查询内容；是整套介绍正文来源 |
| 接待主线 | 内容组顺序、整套介绍发送间隔 | 完整介绍选择 content_sequence 中 initial_delivery=true 的组，再按 delivery_mode 编排文字/附件 |
| 场景话术 | 名称、状态、优先级、主题、人数范围、适用/不适用例句、正文、素材与事实引用、来源 | active 话术加载到线路 Skill；模型优先沿用原文并按上下文调整。pending_review/disabled 不进入 active 脚本列表 |
| 图片与文件 | 素材名称、内容说明、卖点、客户价值、图注、避免承诺、替换文件 | 话术和内容组按素材 ID/键引用；图片排列还受所在内容组和交付方式控制 |
| 版本记录 | 当前包版本、变更记录 | 发布生成线路包；已有会话/已生成任务可能使用绑定快照，不能假定所有老演练立刻换版 |

当前线上线路内容：

| 线路 | 版本 | 启用场景话术 | 首次介绍内容组 | 发送间隔 |
|---|---|---:|---:|---:|
| 桃花＋珠峰 11 日 | `2026-09-27.website-direct-11d-1` | 36 | 11 | 2 秒 |
| 桃花 9 日 | `2026-09-27.website-direct-9d-1` | 33 | 8 | 2 秒 |

一个内容组可以产生文字和多张图片，所以“11 组”不等于“11 条消息”。已知人数会把通用顾问开头换成对应人数内容组。

**目前三个不同编辑对象不能混为一谈：**

- 事实 `knowledge_facts`：提供查询依据。
- 介绍 `content_groups.approved_text`：用于整套介绍直接交付。
- 话术 `fixed_answers.answer_text`：加载进 Skill，供普通问答采用。

它们会在同一个线路包里发布，但文本不是自动同步的。只改价格事实，不会自动改掉介绍正文或问价话术里的旧数字。全局语气也不会自动重写程序按原文发送的介绍。

后台修改话术后，SkillRegistry 会把实际话术替换进 `{{script:...}}` 并附加其他 active 话术，已经不是空 Skill。但 SKILL.md 中的接待步骤仍是代码文件；后台不是完整 Skill 编辑器。

通用话术目前仍来自服务知识文件，没有与“线路场景话术”对等的通用话术增删编辑页。这是当前产品缺口。

## 4. 官网资料库

页面展示两类数据：运行时通用知识模块，以及官网抓取版本。前者与后者的启停范围不同。

- “更新资料”按钮在前端写死为 disabled，不能从这里刷新官网。
- 启用操作当前 API 固定发布为 `playground`；页面也只判断 `ai_enabled && runtime_scope === 'playground'`。
- **实际线上官网源为 ai_enabled=true、runtime_scope=live，已发布第 4 版。** 真实接待可以读取，演练也可以读取。
- 因而当前页面可能把“已真实启用”的源显示成“未启用/启用到 AI 演练”，提示“当前知识不会进入任何 AI 回复”也是错的。若按这个错误按钮重新启用，API 会将范围改为 playground。
- 这里不是实时浏览器；回复读取已发布知识。改官网不会自动改线路 Skill、场景话术和线路图片。

## 5. 系统设置：九个分区

| 分区 | 主要配置/操作 | 当前影响 |
|---|---|---|
| 渠道与收件箱 | Chatwoot 地址、账号、Token、测试连接、同步、Inbox AI 启用 | 控制接入和会话接待范围 |
| Account Webhook | 事件订阅、回调与密钥相关设置 | 控制入站同步；不改变话术 |
| 历史数据 | 历史同步任务、范围/进度操作 | 同步上下文数据，不是回复模板 |
| AI Adapter | mock/http、启用、URL、Token、超时、失败次数、Mock 触发/回复 | 旧适配器。URL/模型选择不改变 V2 的 DeepSeek 模型；但 enabled 仍被真实回复门禁读取，关闭可能停止 V2 回复 |
| AI 接待范围 | 白名单、会话 ID | 直接影响哪些真实会话可接待；当前白名单关闭，按 ai 标签范围 |
| 标签映射 | AI、人工、停止等标签映射 | 影响同步与状态；当前正式回复还有固定 ai 标签判断，并非所有映射都能替换该标签要求 |
| 用户与权限 | 用户、角色、收件箱范围、顾问账号映射 | 后台使用范围及人工分配；与话术风格无关 |
| 顾问通知 | 启用、Chatwoot/Webhook、顾问 ID、机器人 ID、URL/密钥、事件 | 内部通知渠道。线上没有 notification_settings 记录，按默认关闭；单次手机测试成功不等于自动通知已配置开启 |
| 审计日志 | 筛选/查看 | 只读历史，不控制回复 |

当前 V2 模型来自服务端环境配置 `deepseek_model=deepseek-v4-flash`，调用超时 20 秒，真实回复并发 2。没有对应的统一后台 V2 模型设置页。模型温度、输出 token 上限等还有运行时代码常量，不由 AI Adapter 控制。

## 6. 三个隐藏页面并未真正退出

### AI 被动回复

配置字段：enabled、merge_wait_seconds、merge_max_seconds、backlog_seconds，可按全局/Inbox 保存。当前数据库无覆盖记录，默认启用、等待 2 秒、最长合并 5 秒、积压 300 秒。

真实 V2 仍读取启用和合并等待。backlog_seconds 在演练/影子路径使用，但真实回复的新鲜度函数仍固定五分钟，不能认为这里改值能统一改变所有路径。页面写死“演练环境、真实发送关闭”，与其可以影响真实回复的事实不符。

### 沉默客户唤醒

独立策略字段包括名称、阈值、频控、Inbox、有效期和活跃时间；有发布/暂停、候选/周期、运行记录。当前两条 QA 策略均暂停。不是 AI 接待策略里的 V2 时间列表，也不是当前线路 Skill 的统一设置页。

### SOP 定时触达

独立管理 SOP 名称、线路/触发范围、节点时间、消息与素材、客户回复停止、dry_run/live_enabled、发布版本及入组。

V2 自动线路接待的完整介绍由线路内容组交付；到期沉默通过 journey_trigger 调主 Agent。不能把旧 SOP 编辑器每个节点里的固定文案，等同于当前 V2 沉默必发文案。

线上有九个 SOP 定义：五个 paused、四个 running。running 中，11 日默认 SOP 和未选线路默认 SOP 为演练；9 日默认 SOP 有 live 标记；另一个 11 日测试副本为演练。总 LIVE_SOP_ENABLED=false，所以不能看到 running 就认为真实主动触达已开启。

## 7. 当前实际开关与生效时机

| 项目 | 线上只读结果 |
|---|---|
| 全局客户消息发送 | 开 |
| 出站模式/Chatwoot 写入 | live / 开 |
| 默认引擎 | V2 |
| 接待范围 | ai 标签范围，白名单关 |
| 策略内沉默启用 | 开 |
| 真实主动 SOP 总开关 | **关** |
| 官网第 4 版 | **真实与演练可用** |
| 自动顾问外部通知 | **默认关** |

配置生效要区分四种情况：

1. 开场、发送间隔等由程序使用的内容：新决策读取，但不会倒回去重发老会话的开场。
2. 语气、目标、留资偏好：进入模型提示；不是每个词句都确定性执行。
3. 线路/SOP 发布内容：新版本与已有会话/任务快照并存；验收应同时看会话实际绑定版本。
4. 模型与运行环境开关：来自服务器配置，需要按运行进程加载方式生效；后台策略保存不能代替部署/重启这类变更。

线路启停和 AI 接待策略两个页面都可能提交整份 reception-config，且页面草稿不总是随远端变化刷新。这会有旧页面草稿覆盖较新字段的风险；本次没有通过改值复现，不将它写成截图事件的已确认原因。

## 8. 评价与建议优先级

现状是“新 Skill 接待＋旧策略/任务配置＋运行开关”并存，没有完成单一配置入口的收拢。主要问题是配置来源、执行路径和页面显示不一致。

建议下一轮只处理与回复直接相关的收口：

1. 开场只维护可见的有序消息，不再隐式补问句；保持现有业务原文。
2. 线路的介绍、场景话术、素材、间隔归到同一个线路编辑入口，明确相同事实重复在哪些正文里；增加通用话术入口。
3. 修正官网启用范围、版本记录、真实发送等错误状态显示。
4. 沉默只保留一套业务配置，并显示实际总开关；先拆除旧页面对新链路的实际依赖，再删除旧页面和代码。
5. 删除不再被 V2 使用的配置；仍有用途的合并等待等运行参数从旧页面迁出。不要仅隐藏页面后称为清理完成。

不建议现在再次重做日志或增加配置解释面板。先使可编辑项与实际行为一一对应。
