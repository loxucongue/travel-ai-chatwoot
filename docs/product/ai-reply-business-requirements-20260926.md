# AI 回复效果：业务要求总表

整理日期：2026-09-26。用途：作为后续回复质量设计和业务验收的需求基线。

**目标：像熟悉产品的台湾旅游顾问，理解客户当下的问题，给出准确、自然、有帮助的答复；在合适时机提供资料、取得一种有效联系方式或交给人工，并在客户沉默时有分寸地跟进。**

本表总结“业务要什么”，不宣称现有系统已经做到，也不以历史测试通过数量代替达标结论。技术方案、模型选择、模块结构和测试数量不属于客户回复效果本身。

## 一、语气、信任感与信息分寸

| ID | 业务要求 | 验收时具体看什么 | 来源 |
|---|---|---|---|
| T01 | 使用自然台湾繁体中文 | 用词、语序、称呼和节奏自然，不只是简体转繁体 | D15、D21 A11、H质量 |
| T02 | 亲切、柔和、有礼的顾问口吻 | 不像客服公文、系统通知或审查报告，不靠密集“喔、～、表情”制造亲切 | D15、D21 A11、H质量 |
| T03 | 避免业务不认可的用词与系统腔 | “標間、專項顧問、匹配方案、内部资料未审核”等不能成为常态；业务曾明确要求避免“比較” | D15、D21 A11 |
| T04 | 简洁、直接、有重点 | 简单问题可一句答完，多问题再适度展开，不强制每次固定字数或完整套餐 | D20 B6、D21 A04/A13 |
| T05 | 少兜底、少推脱、少重复免责声明 | 不连续堆“可能、以实际为准、请顾问核对、请医生评估”；只讲影响当前答案的必要条件 | H信任、D21最终补充 |
| T06 | 已知且条件明确时肯定回答 | 不把确定报价、报名条件和已公布服务故意讲成不确定 | H信任 |
| T07 | 不重复问候与机械承接 | 老会话不重新欢迎、自我介绍；不每轮都以“收到、了解、好的”开头 | D15、D21 A01/A11 |
| T08 | 介绍有具体帮助和产品吸引力 | 讲客户在意的安排、差异与特色，不泛说“品质好”，也不为营销添加虚假保证 | D21 A04/A09/A12、H质量 |

“避免比較”是历史品牌表达偏好，不是“这个词不属于台湾用语”的语言学结论。如何避免不自然表达由设计解决，不应把全局替换成“較”写成业务需求。少说边界也不等于删掉真正的价格或服务适用条件。

| ID | 业务要求 | 验收时具体看什么 | 来源 |
|---|---|---|---|

| U02 | 能理解上下文与省略追问 | “那回程呢”“波密也是吗”“自己要准备吗”承接正确对象，不换成另一主题 | D21 A23、H历史多轮反馈 |
| U03 | 多问题逐项回答 | 价格＋接送、完整资料＋小费等都要处理；一个未知问题不吞掉已知答案 | D21 A24 |
| U04 | 区分咨询、选择、比较与索取资料 | “可以先问行程吗”不等于“把整套图发来”；了解另一条不等于已经改线 | D21架构说明、H历史资料请求反馈 |
| U05 | 记住客户明确提供的资料 | 人数、时间、选线和联系偏好确实保留，不只在回复里说“记下了” | D21 A20、H历史资料保存反馈 |

| U08 | 单纯补资料只需自然承接 | 客户只说“4位”，不重新介绍品牌、住宿、车辆，不自动查价、查余位 | H跟进、D21 A20 |
| U09 | 不凭空推断客户状态 | 询问集合不代表“考虑中”；报日期不代表请求查位；假设人数不代表实际人数 | D21架构说明、H历史状态反馈 |
| U10 | 对必要确认与无效重复作区分 | 客户主动重复确认可以再回答；不能因提过该主题而拒绝，也不重发整个介绍 | D21 A23、H历史酒店追问反馈 |

## 三、首次接待与资料展示

| ID | 业务要求 | 验收时具体看什么 | 来源 |
|---|---|---|---|
| M01 | 开场简短礼貌、品牌明确 | 普通问候和直接咨询线路两种入口都能自然接待；开场支持运营配置的文字、图片、视频 | D15、D21 A01 |
| M02 | 未选线时帮助选线 | 不先倾倒两套资料，不强迫客户填完人数、日期才回答 | D21架构说明、H历史V2目标 |
| M03 | 客户需要完整介绍时有清楚顺序 | 品牌简述→对应行程图及精简说明→相关景点/卖点→酒店→车辆→必要尾问；已讲内容不机械重放 | D21 A01/A04/A05、D22 |
| M04 | 行程图必须在照片前 | 9日、11日分别发自己的行程图，再发本次介绍中的景点、住宿、车辆照片；不能用风景图代替行程图 | D20 B1、D22、H跟进 |
| M05 | 逐条发送，不一次堆完 | 图文介绍按业务要求约1–2秒间隔，保持可读性；不把多段拼成大段文字 | D15、D21 A03 |
| M06 | 卖点清晰，不罗列地名 | 桃花秘境、珠峰等特色与当前线路匹配；完整行程信息可保留，普通回复不背每日走法 | D21 A04 |
| M07 | 图文自然配合 | 说明发的是什么和相关重点，不机械逐张报幕、不重复规格；正文与图片实际内容相符 | D15、H历史图片重复反馈 |
| M08 | 完整介绍最后至多一个必要问题 | 问题不能被后续照片淹没，也不能正文问人数、末尾再问日期或同行关系 | D21 A10 |
| M09 | 客户插话能及时打断 | 先处理新问题，停止过期介绍；是否继续剩余资料取决于新需求 | D21 B6/A03、P20交付要求 |
| M10 | 索取和重发必须有实际资料 | 请求对应图/文件就交付；明确未收到或要求重发可重发；缺件明确处理，不谎称已发 | D21 B1/A05/A24 |
| M11 | 不重复提供已交付资料 | 不反复发同一图片；不再以“替您整理完整行程”为新价值或留资借口 | H跟进、D21 A20 |
| M12 | 高原注意事项是可交付文件 | 留资后的相关服务能提供正式注意事项，客户明确索取也应可提供；不能拿文字回答或待办代替附件已送达 | D21 A16、H信任 |

M04约束本轮完整介绍的顺序；客户单独索要一张车照时，不应因此强制再发整套行程。M12的“留资后发送”是原始要求；不是“必须留资才允许获取公开资料”的授权。是否所有留资都无条件自动附发，历史记录未完全统一，见待确认项。

| A08 | 医疗服务边界讲清楚 | 不安排随团医师，导游提供既有就医协助；不能说导游代替医生判断/开药，也不能把“不允许开药”扩大成“不提供任何药品” | D21 A15、H历史服务审阅反馈 |

## 属于技术方案或参数，不应写成业务硬要求

- 一个主Agent、每条线路一个Skill、Flow分类、状态机、回复计划、独立表达层、核验器数量等是实现手段。业务效果不以是否采用某种模块数量判定。
- “Flow必须限制模型只能做某阶段”“所有回复必须走固定步骤”并非业务目标；若让新问题被旧流程绑住，反而违反U01。
- 后续120分钟、考虑至少24小时、最多延期次数等来自方案或当前默认配置。业务明确的是首次约一分钟、有价值才跟进、考虑给空间、预约守时和拒绝停止；不能把所有技术默认都当成业务永久规定。
- “普通问答P50≤8秒、P95≤15秒”等是P20提出并用于执行的工程验收目标；业务原始诉求是快、稳定、自然，指标应有测量口径。
- 30条风格锚点、100条单轮盲测、20条旅程、90%直接可发率是2026-09-26设计草案建议，并非已取得业务确认的固定标准。
- “每次提供一个额外卖点”“每次都问一个问题”“每次都建议留联系方式”均不能成为通用规则。
- 当前阶段曾关闭主动跟进，不代表业务取消了沉默唤醒需求；部署开关状态和期望能力分开记录。本轮没有核查生产开关。

## 仍未取得明确口径，不能编成产品事实的事项

1. **两条线路各自的最低成团人数、保证出团条件。**4–10人不能作答案，历史末尾的确认问题未见答复。
2. **小费30元的分项含义。**司机与导游合计还是各自计算，以及全程总额的计天规则。
3. **具体折扣、特殊人数报价、实时余位、特定日期成团状态。**优惠存在已有依据，具体数值和即时状态需实际数据。
4. **特殊中转交函、未批准指定酒店/车型、特殊拼房及其他月份方案。**按客户当前请求核对，不每轮主动扩展全部未知项。
5. **全部户外区段的便携氧气供应。**现有条件性安排不能推出全区段供应或全区段不提供。
6. **高原PDF的默认触发范围。**原文要求留资后发，后续记录又强调明确索取；需明确是否所有留资都自动附发，或仅相关需求触发。两种情况都不能虚报送达。
7. **台湾风格的最终业务认可范例。**方向明确，但没有一份足以覆盖各场景、经业务最终签定的统一语气标准；也没有统一的固定字数或语气词配额要求。
8. **顾问新消息提醒的分流细节及手表验收方式。**转人工手机提醒明确；所有AI处理中消息是否也推送、如何降噪、手表是否通过手机镜像，尚需具体口径。

这些待定事项不应阻塞已有确定答案，也不应成为反复索要联系方式、日期或推给顾问的借口。

## 后续使用方式

每次优化绑定本表ID，记录原始客户问题、必要上下文、业务期望、实际回复和实际动作。分别标记“内容正确、表达认可、动作完成、真实渠道验证”，避免只统计接口成功。

历史业务文档明确但尚未实现的属于开发缺口；业务尚未提供的产品数值属于事实缺口；本轮提出的评分方式属于待确认验收方案。三者不得互相代替。
