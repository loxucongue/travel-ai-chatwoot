# V3：单线路 Skill 接待

V3 是独立引擎，当前通过演练场选择使用；正式会话仍使用 V2。不新增配置页面，也不迁移正式客户。

三个标准 Skill 目录位于 `backend/app/reception_v3/skills`：`tibet-reception`、`peach-9d-2027`、`peach-11d-2027`。每个 `SKILL.md` 含 YAML `name`、`description` 和执行方法。注册器启动时读取索引；加载线路时将当前后台事实、场景原话、完整 SOP、图片引用及顺序附入正文，不复制另一套可编辑数据。

每轮预加载通用接待和已知线路。尚未选线时只提供两条线路名称、别名及 Skill 描述；模型通过原生 `load_skill` 工具读取所需线路，比较时可同轮加载两条。官网补充事实由 `get_service_facts` 按需返回，不再默认将两条线路及所有官网知识整包塞入提示词。配置修改在下一次模型运行时读取，已经开始发送的介绍使用已保存的计划。

运行记录的 `loaded_skills` 保存真正加载的名称及内容摘要，`skill_tool_calls` 保存工具参数和结果摘要；底层 `logs` 保留每次模型 HTTP 轮次及最终话术、图片引用。索引出现一个名称不代表正文已经加载，正文加载也不等同于逐句采用。

同一个模型处理三个事件：客户消息、介绍完成、沉默到期。没有 V2 Flow 分类、话术审核、裁剪和反复改写。结构错误最多修正一次 JSON；模型最终文字直接交付，引用话术直接取原文。

第一次消息先发送配置开场，按客户会话只执行一次；是否含「你好」不参与判断。模型随后承接广告线路或帮助选择。确认线路后用 `start_introduction` 引用整套配置，不让模型重打一遍。

交付队列按配置秒数发送；普通插话保存，整套介绍发完再统一回答。模型判断停止、改线或转人工时取消剩余介绍。介绍完成后一定产生新的模型事件，根据最新人数、日期、期间问题决定结尾的一个问题。没有固定尾问拼接。

默认按通用沉默间隔配置定时运行模型，不读取 V2 的独立间隔。模型可以指定 `next_check_minutes` 覆盖下一间隔，适合明确预约；`null` 使用配置。`stop_followup` 表示结束自动评估。从最后一条实际交付后计时；没有输出则从本次评估结束计时。到点可发送、继续等待或结束；拒绝主动联系和人工接管状态由服务端记录。

数据库复用演练会话、运行记录和消息字段；V3 状态放在 `controls.v3`，旧 Worker 排除 V3。重启后延续未发消息；每次最多发送一条，进程停顿后不把欠下的间隔压成瞬间刷屏。

当前交接是沙盒状态，不向 Chatwoot 创建任务或发送消息。生产接入需要单独把同一决策协议连接到实际交付适配器，不能把沙盒通过等同于真实顾问收到。

验收重点：连续对话、两条线路顺序、介绍期间问题合并、介绍末尾问人数、已知人数不重复、改线与停止、留资交接、三分钟和五分钟计时、重启恢复与配置开场原文。
