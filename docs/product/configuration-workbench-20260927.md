# 当前配置入口与生效方式

本次改造后的配置说明。改造前的问题清单见 `current-configuration-map-20260927.md`；那份是历史核查记录，不作为新版操作说明。

## 四个入口

| 页面 | 保留功能 | 保存后如何生效 |
|---|---|---|
| 公共接待 `/ai-strategy` | 开场与语气、通用话术、留资与交接、沉默跟进 | 保存到数据库 `route_reception_config`，后续新决策读取 |
| 线路配置 `/products` | 线路启停、入口信息、介绍内容与顺序、事实、场景话术、素材、版本 | 发布线路包；线路 Skill、事实工具和交付计划读取同一线路版本 |
| 通用知识 `/knowledge` | 共用知识展示、官网知识启停、使用范围 | 选择“仅演练”或“真实接待与演练”；读取已发布版本 |
| 系统设置 `/settings` | 渠道、Webhook、运行参数、接待范围、历史同步、标签、人员、顾问通知、操作记录 | 各服务读取对应设置；模型名称、超时、并发显示实际服务端值 |

演练、会话、人工接管和回放仍是工作页面，不另建同类配置入口。保持现有字体、配色、侧栏、表单和卡片样式。没有重做日志页。

## 公共接待

| 设置 | 作用与边界 |
|---|---|
| 开场消息、附件、顺序 | 首次客户消息使用配置列表；不由模型改写，不自动补问句。演练每个会话视为一个客户 |
| 开场消息间隔 | 开场各项之间的间隔；不替代线路介绍的发送间隔 |
| 语气、接待目标、接待说明 | 输入主 Agent 的表达与决策上下文；不会重写按原文交付的开场和固定介绍 |
| 通用话术 | 名称、适用场景、原文、启停；启用项输入主 Agent，按场景沿用。停用项不再进入新决策 |
| 主动留资、联系渠道 | 给 Agent 的业务指令；关闭主动索取不阻止承接客户主动提供的联系方式。不使用回答两轮等固定计数规则 |
| 多人交接人数、目录外需求 | 给 Agent 的处理指令；不把人数阈值等同于最低成团人数 |
| 沉默跟进开关 | 是否创建、执行沉默培育；不代表到点必发，也不替代整套线路介绍 |
| 用于真实客户 | 控制正式沉默执行；首次迁移继承旧环境开关，保存后以此设置为准。真实发送仍受顶部总开关、会话接管和渠道窗口影响 |
| 跟进间隔 | 第一项从回复结束算，后续从上次跟进算；只保留当前 V2 的一套时间编辑器 |
| 时段、每日次数 | 限定主动触达时间与频次 |

开场最后一项可以是图片或视频，也可以只有素材。线路选择按钮附在最后一条已有文字上；没有文字就不另造一条。已有两条开场正文不会因发布本次代码而被改成一句。

## 线路配置

- 入口与名称：线路名称、选线按钮名、入口消息与匹配信息。
- 线路接待说明：加载该线路 Skill 时读取 `ai_guidance`。
- 整套介绍：按配置内容组、顺序、图片、发送模式和线路间隔交付。普通问题排队集中回答的现有执行链保留。
- 场景话术：适用问法、话术原文、引用事实与素材；启用的话术装入对应线路 Skill。
- 事实：为问答和解释提供数据，不自动改写已保存的话术正文。
- 素材：素材文件、说明、与内容组及话术的引用；开场素材在公共接待单独维护。
- 版本：已有客户可继续使用绑定快照；新发布不静默改写已冻结的介绍和发送计划。验证新内容请建立新演练。

“事实”“固定介绍”“场景话术”用途不同，仍分别维护。价格变更涉及这几处时，应一并修改相应文案；当前没有自动重写功能。

## 系统设置

| 分区 | 实际作用 |
|---|---|
| 渠道与收件箱 | Chatwoot 连接、收件箱同步、收件箱 AI 开关 |
| Account Webhook | 接收消息事件的连接配置 |
| 运行参数 | 全局/收件箱的被动回复启停、消息合并等待与最长等待；展示实际模型、超时、并发 |
| AI 接待范围 | 正式会话范围；不修改话术 |
| 历史数据 | 历史回填，不重放为新客户消息 |
| 标签映射 | AI、人工、拒绝等状态标签对应关系 |
| 用户与权限 | 已有账号管理功能 |
| 顾问通知 | 通知渠道和接收人；接口接受不等于设备已送达 |
| 操作记录 | 配置和管理操作记录；沿用现有页面 |

顶部“全局消息发送”仍是唯一整体出站开关。模型凭据在服务端环境中维护，前端不提供一个不参与 V2 调用的 Adapter 地址。

## 删除与兼容

已删除旧被动回复、独立唤醒、SOP 编辑/审核页面及路由，删除其配置 API、请求模型和专用样式。原有共用运行记录组件提取后继续供回放页使用。

删除的 API：`/settings/ai`、`/settings/ai-adapter`、`/automation/reply-policy`、`/sops*`、`/wakeup*`。运行参数迁至 `/settings/reply-timing`。公共接待只接受 `PATCH /automation/reception-config`，不再接受整份 `PUT`。

各页只提交自己改动的字段，服务端合并当前保存值。因此切换线路启用状态，不会用旧页面草稿覆盖刚保存的开场。

仍被线路发送、演练和历史任务引用的 SOP 执行器、数据表、版本快照保留；它们不是另一套配置页面。旧 V1 内部字段保留读取兼容，不能通过新版配置 API 编辑。旧自定义规则迁入可见的接待说明；其内容不会因删页直接丢失。旧 AI Adapter 开关不再阻断正式回复。

配置影响时点：公共接待影响后续决策；线路发布影响新绑定；沉默间隔影响新入组；出站总开关与正式沉默开关在执行时读取。已经发送的内容不会追改，已冻结的发送计划不重新生成。
