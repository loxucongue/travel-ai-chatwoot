# 话术驱动接待：配置页面与 SOP 设计

后续细化：完整页面、字段、迁移与执行合同见 [接待后台重设计](reception-workbench-design-20260927.md)；[可点击原型](prototypes/reception-workbench.html) 仅作设计预览。以下实施状态是该轮记录，不代表原型已接入实际系统。

## 已确认的业务口径

- 开场只由“客户首次进入”决定，与客户是否使用某个问候词无关。演练的一个会话视为一个客户。
- 广告入口消息已经明确线路时直接接待该线路；没有明确线路时帮助匹配。不要求所有客户先回答同一套问题。
- 线路确认后，按配置的顺序和间隔发送整套介绍。期间普通问题先记录，整套介绍完成后集中回答。
- 客户明确停止、改线、要求人工，以及顾问实际接管，应结束原线路介绍。不能把这些事件当作待回答的普通问题。
- 常见问题优先用话术原文，允许模型结合客户已知信息调整称呼、衔接和组合。最终正文不再交给另一个模型审核或改写。
- 服务目标仍是提供资料、解决顾虑、主动争取一种联系方式并交给顾问，沉默时提供相关新价值。

## 最小架构

接待入口读取客户状态与当前线路，向同一个主 Agent 提供通用话术、当前线路话术和必要事实。模型选择适用话术、处理复合问题、决定留资或交接。执行端负责把文字和素材真正发出，保存进度与待回答消息。

不新增一套 Flow 分类器、话术审核器、字词替换器或多 Agent 系统。既有发送通道、素材库、任务表和发送记录继续使用。

Skill 是运行时读取的内容包，不要求运营编辑 Markdown。后台数据是唯一编辑来源，加载 Skill 时组合最新生效的配置；不能同时维护一份后台话术和另一份手写 Skill 话术。

## 后台所有配置页面的调整

| 目标页面 | 内容 | 当前页面的处理 |
| --- | --- | --- |
| 通用接待 | 首次开场、品牌与语气、通用场景话术、留资与交接话术、沉默节奏与话术 | 合并 AI 接待策略中的相关内容；取消另设被动回复、唤醒策略的重复入口 |
| 线路接待 | 线路信息、广告入口消息、完整介绍 SOP、线路场景话术、线路事实、素材 | 在现有线路管理上收拢，不再将同一段文字放到“线路资料”和“固定问答”分别维护 |
| 通用知识 | 官网服务事实、适用范围、来源；通用图片和文件 | 保留官网资料库，区别“业务事实”与“表达范例” |
| 连接设置 | Chatwoot、模型、顾问通知和必要的运行开关 | 保留实际使用的连接配置，移走业务话术与 SOP |

演练场、客户会话和人工待办是工作页面，保留。版本记录作为各配置页的历史记录，不单独增加发布中心。

“回放与资料”应拆开：素材入口合并进线路/通用素材；历史回放进入演练记录。旧审核评分、审核修订轮次不再作为 V2 的主界面内容，历史记录保留其当时版本含义。

独立 SOP 编辑器在迁移到“线路接待—完整介绍”后删除。不能只隐藏菜单而继续让旧页面写入另一份实际生效配置。删除页面时同时移除其独占 API、类型、调用代码和测试；有其他使用者的接口先迁移调用者。

“系统保护（只读）”不是业务配置，本次已移除页面组件及其专用查询。不会用只读保护说明占据话术编辑空间。

## 一条话术怎么配置

编辑内容只需要：名称、适用场景、问法示例、话术原文、关联素材、启用状态。必要时补“不适用场景”和人数等真实适用条件。分类和优先级放到次要位置，不要求运营配置关键词规则。

通用话术和线路话术使用同一结构。线路事实决定价格、住宿和行程条件；通用话术可以提供表达方式，不能覆盖具体产品条件。有同场景专属话术时优先使用线路话术。

模型可以省略已回答过的介绍、替换称呼、把两段相关话术合为一个答案，也可以只摘取客户关心的部分。不要求拼接整段无关卖点。配置的开场与完整介绍 SOP 直接按原文交付；问答话术作为模型优先使用的范例。

事实与话术冲突，应在内容维护时修正来源，不能在发送后靠正则替换补救。不能依据“11 日比 9 日多两天”自行承诺更轻松；这种产品判断必须有线路依据。

## 图片、视频和文件

- 话术引用现有素材编号，不把图片链接埋进文字，也不重复上传同一文件。
- 线路话术可从本线路素材中选择，并可引用明确属于通用知识的资料。不要默认混用另一条线路的行程图。
- 编辑器显示名称和预览；SOP 编辑器另外控制文字/素材顺序、组内间隔和组间间隔。
- 同一素材可以被多条话术引用。复制话术只复制引用，不复制文件。
- 一次执行开始时记录实际使用的文字、素材版本和顺序；素材更换影响之后开始的执行，不把已经发送的一半替换成另一版。
- 缺失素材显示具体缺失项和实际发送状态，不能记录为已经发送。

本次已扩大现有线路话术编辑器的素材选择范围：由“当前内容组”扩展为“本线路全部已登记素材”。通用素材跨页面引用仍需在后续配置合并时接通。

## 两种入口

1. 广告产生的消息与已配置入口一致，或者消息明确表达一条线路：绑定线路并加载对应内容；不重复询问客户想选哪条线路。入口配置作为数据维护，不继续在 Python 中新增中文判断词表。
2. 没有明确线路：主 Agent 使用通用接待话术，结合已有条件推荐或询问一个有助于选择的问题；确认后开始线路介绍。

首次开场和线路识别是两件事。先发配置开场不能把第一条客户消息标成“问题已经回答”。第一条消息中的线路意向、人数和问题，必须继续交给接待处理。

日志记录线路来自“入口配置”“客户明确选择”或“咨询后匹配”，并保留对应消息，便于发现误判。

## SOP 与客户问题的结合

### 完整介绍

线路确认 → 冻结本次介绍内容 → 第一组 → 按间隔发送后续各组 → 全部完成 → 合并期间的问题 → 主 Agent 回答 → 再决定留资或沉默跟进。

整套介绍使用配置顺序，包括行程图优先于照片。不是由模型每轮重新组织一套，也不是介绍完一个组就等待模型再次判断。需允许设置组内消息间隔和组间间隔，但不要出现两处互相覆盖的时间配置。

### 介绍期间收到普通问题

保存原消息和次序，将问题置为待处理；当前介绍继续。多条消息合为一次上下文，人数更正以最新表达为准，但不能丢弃前面未回答的问题。不要每条消息重新启动整套介绍，也不要把问题标为已处理。

最后一条介绍提交完成后，立即将待处理消息交给正常问答队列，不再等待沉默计时。回答需结合客户期间的问题与已经实际发送的资料，避免复述刚发过的整套介绍。

若介绍发送失败，应结束介绍执行并处理积压问题或交给人工，不能让问题无限等待。恢复执行依据实际发送记录，不仅依据“执行到第几个组”的数字。

### 立即中止的情况

停止发送、转人工、明确改线和人工接管不进入普通问题队列。用现有客户事件和会话控制表达这些动作，不增加话术审查模型。客户已提供联系方式时应进入交接，而不是为了完成介绍继续销售。

### 与沉默唤醒区别

沉默计时从介绍及待回答问题处理完之后开始。介绍期间收到消息，不应取消介绍，但应取消旧的沉默候选。一次沉默触达期间收到新消息则优先处理客户，不延续过期触达。

用户选择整套发完的代价是插问会等待剩余介绍的时间。页面应显示消息数量和预计发送时长，供业务调整组数和间隔，不擅自改变已确认的发送顺序。

## 配置生效与诊断

页面保存后展示生效内容和一键演练入口。一次演练必须明确使用哪个线路版本和话术配置，不通过“审核通过”表达已生效。

接待记录保留：客户输入、线路来源、使用的线路 Skill、提供给模型的话术与事实版本、模型最终正文、实际发送项目、SOP 进度、待回答消息、留资/人工状态、模型调用数及耗时。只保留问题定位所需数据，不继续展示一串已不存在的审核节点。

## 执行链改造的验收

1. 两个新演练会话各发一次配置开场；同一会话重复相同文字不重复开场。
2. 有明确广告线路时加载该线路；无明确线路时匹配；第一条消息的真实问题不会被开场吃掉。
3. 两条线路分别完整发送其配置的各组文字和素材，顺序和间隔可从实际记录核对。
4. 在不同组之间插入三条普通问题，介绍不中断、每份素材只发送一次，结束后问题全部得到处理。
5. 插入停止、人工、改线和联系方式事件，按相应动作结束原介绍。
6. 修改线路或通用话术后，新一轮能读取修改；停用话术不再提供给模型。
7. 普通问答没有审核/改写请求；模型正文与实际交付正文一致，配置 SOP 的原文与实际项目一致。
8. 介绍及问题处理完后才进入留资/沉默；顾问接管后不继续自动销售。
