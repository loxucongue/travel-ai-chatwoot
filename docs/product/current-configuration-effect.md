# 当前配置如何生效

更新时间：2026-09-08  
适用版本：`split-realtime-reply-v33` / `split-silence-touch-v10`

本文说明运营页面保存的配置如何进入实时接待、线路主线、逐字固定回答、沉默跟进和真实发送门禁。

## 1. 三类配置

| 页面 | 配置范围 | 生效方式 |
|---|---|---|
| AI 接待策略 | 全部启用线路共用 | 保存到数据库；下一次客户决策或新沉默轮次读取新值 |
| 线路管理 | 单条线路 | 校验后发布新的线路包和不可变 SOP 版本 |
| 系统设置 | 真实发送总开关、AI 标签范围、临时白名单 | 每次建任务和真正发送前重新读取 |

“线路内容”和“AI 可用资料”已经合并。业务人员只维护一份线路资料：事实、内容组、图片、主线顺序和固定问答。

## 2. 实时客户消息

```text
Chatwoot 客户消息
-> 全局发送开关
-> 精确 ai 标签
-> 可选会话白名单
-> 人工接管、客诉、拒绝联系、渠道窗口、幂等检查
-> 客户理解模型提取语义与逐字证据
-> 代码规划动作、线路、8 人规则、留资、唯一追问、事实和素材
-> 标准问答命中则逐字输出；否则生成台湾顾问话术并执行事实核验
-> 发送前再次读取标签、白名单和全局开关
-> 发送并更新客户档案、已覆盖内容和旅程状态
```

任何一个发送门禁不通过，普通自动文字和图片都不能建立或完成发送。

## 3. AI 接待策略

页面保存接口：`PUT /automation/reception-config`。

保存成功后：

- 新客户消息立即读取新配置。
- 已建立的沉默旅程保留发布时的不可变线路版本；新一轮旅程读取新策略。
- 保存本身不会发送消息。
- 返回 `422` 代表校验失败，配置没有发布；页面会显示后端错误原因。

### 基础接待

| 配置 | 当前值 | 实际作用 |
|---|---:|---|
| 接待目标 | 先回答客户，再自然取得一种有效联络方式 | 进入客户可见生成节点 |
| 表达语气 | 亲切专业 | 与固定台湾顾问表达合同合并 |
| 自定义表达语气 | 运营可编辑 | 同时进入实时回复和沉默文案生成，只影响措辞、语气和句式 |
| 单次回复上限 | 200 字 | 生成提示和代码最终校验共用同一个有效值 |
| 单次最多图片 | 2 张 | 普通模型回复单轮可选图片上限；静态主线每个内容组使用该组审核图片 |
| 全局补充说明 | 运营可编辑 | 只影响客户可见生成，不进入事实核验和发送门禁 |

普通接待不主动提及 AI、机器人、模型或自动化，以 China2Go 旅遊顧問角色服务。客户直接询问身份时，代码使用固定的如实说明，并提供转真人选项。

### 留资

人数和日期不是索取联系方式的硬性前提。代码主要判断：

- 是否已经提供具体价值。
- 是否先回答了当前问题。
- 客户是否已给联系方式或明确拒绝。
- 当前是否适合只推进一个 LINE、微信、电话或 Email 动作。

客户说日期不确定后会记录 `departure_undecided`，不再追问日期。此时可以用“发送完整行程、以后随时联络、日期确定后再核对”等理由自然留资。

### 线路与换线

- 只有页面启用的线路会进入客户理解、快捷选项、规划器和旅程。
- 每条线路可维护关键词标签；只属于一条启用线路的具体关键词会提高该线路优先级，共用词或冲突词不会强制选线。
- 关键词只帮助理解线路，不绕过换线确认、事实校验或转人工规则。
- 未选线路时只说明 9 日与 11 日差异并让客户选择，不发送线路图片。
- 客户明确改问另一条已启用线路时可以换线，并按配置保留人数、日期和预算。
- 资料外线路不会硬套桃花事实。

### 大团和转人工

当前大团阈值是页面有效配置中的 **8 人**：

```text
客户理解模型提取人数和逐字证据
-> 代码验证人数
-> 7 人继续 AI 接待
-> 8 人或人数范围上界达到 8，代码执行转人工
```

大团、已留资或主动要求真人时，代码先建立人工接管状态，再只允许当前终止任务发送一条等待说明和最多一组审核素材，最后移除 `ai` 标签。投诉、退款和合同争议不附带营销素材。

## 4. 线路管理

页面保存接口：`PUT /automation/route-products/{route_variant}/content`。

点击“校验并发布”后，后端会校验：

- 线路名称、选择名称和入口文案。
- 事实文本和来源。
- 内容组、图片绑定和主线顺序。
- 台湾客户文案，不允许大陆客服词或内部操作备注。
- 标准问答的单一生效状态、例句、内容组和图片引用。
- 素材文件、哈希、尺寸和线路归属。

全部通过后才原子发布新线路包；正在执行的旧旅程不会被中途改写。

### 线路内容

每个内容组是一项可复用的业务内容，包含：

```text
用途
客户可见审核文案
事实依据（系统维护，不要求运营手填 ID）
图片素材
主线位置
是否确认线路后立即发送
```

编辑使用右侧抽屉，不再拆成“线路内容”和“AI 可用资料”两个重复页面。

### 接待主线

`content_sequence` 是实时对话和沉默跟进共用的唯一顺序。客户直接问题永远优先；回答过或发过的组会标记已覆盖，不重复发送。

当前 9 日顺序：

```text
[立即] 行程总览
[立即] 桃花亮点
[立即] 饭店与房内设备
[立即] 车辆与车内设备
[后续] 住宿补充
[后续] 布达拉宫与八廓街
[后续] 扎基寺
[后续] 温和承接
```

当前 11 日顺序：

```text
[立即] 行程总览
[立即] 珠峰絨布旅館
[立即] 桃花亮点
[立即] 饭店与房内设备
[立即] 车辆与车内设备
[后续] 住宿补充
[后续] 布达拉宫与八廓街
[后续] 扎基寺
[后续] 温和承接
```

线路确认后，所有勾选组在同一接待时点按页面顺序逐组送达：先发审核图片，约 3 秒后发对应审核文案，下一组再间隔约 3 秒。每一段发送前都会重新检查客户是否回复；客户一旦插话，剩余旧主线立即停止并优先回答当前问题。未勾选组留给客户后续提问或沉默节点。留资不要求整条主线全部完成；客户不确定或不回答某个字段时，系统会继续提供价值，不会一直追问。

### 线路级标准问答

标准问答页面只维护一份客户可见内容：

- 名称和单一生效状态：`已启用 / 待审核 / 已停用`。
- 客户常见问法与排除问法。
- 客户实际收到的逐字回答正文。
- 对应线路资料、图片和只读来源位置。

“已启用”并发布线路后立即参与匹配；“待审核”和“已停用”都不参与匹配。主题分类、事实 ID 和匹配优先级属于系统内部字段，不要求运营填写。官网导入项的回答正文就是官网原话，不再额外保存一份“官网原始话术”供对照。

运行时只有满足以下条件才命中：

```text
线路已确认
+ 回答状态为已启用
+ 当前客户文字命中正向例句
+ 没有命中排除例句
+ 不是多主题、转人工、健康、实时团况或线路比较等特殊场景
```

命中后正文不会进入生成模型，100% 使用页面发布的文字。已启用的官网原话在发布时完成来源、长度、素材和风险状态校验，运行时不再交给模型改写或二次核验；没有明确命中时回到受控生成和独立事实核验，不按宽泛主题猜一条标准回答。

当前网站快照已导入：9 日 21 条、11 日 22 条。安全内容启用 12/13 条；各有 9 条风险说法保留为待审核，包括无购物赔偿、年龄政策、孩童适宜性、饭店供氧浓度、车辆年份和“移动氧舱”等原话。通用回答不能夹带这些待审核内容。

### 图片素材

每张正式图片同时维护：画面内容、具体特色、客户价值、推荐话术和禁止说法。发送端按素材 ID 与哈希绑定，旧图片版本仍保留供已开始的旅程审计。

## 5. 沉默跟进

运营可在 `AI 接待策略 -> 沉默跟进` 增加、删除和排序时间节点，最多 20 个，不固定为 6 个。

```text
客户最后一次消息或上一项成功触达
-> 到达下一个配置时间
-> 重新检查全局开关、ai 标签、白名单、人工状态、时间窗和每日上限
-> 从当前线路顺序选择下一项未覆盖内容
-> 有内容：生成或发送审核文案与素材
-> 没内容：no_action，不凑次数、不占用发送频次
```

勾选的即时主线不依赖沉默开关。关闭沉默跟进后，确认线路时仍会发送勾选组，但不会建立后续定时触达。

客户一回复，当前沉默轮次立即取消；AI 回答后按最新状态建立新一轮。沉默文案禁止“看了吗、满意吗、怎么没回复”等纯催问。

## 6. 真实发送门禁与白名单

真实自动发送必须同时满足：

```text
全局发送开启
+ Chatwoot 会话当前存在精确 ai 标签
+ 白名单关闭，或会话编号在白名单
+ Inbox 允许自动接待
+ 没有人工接管、客诉、拒绝联系或黑名单
+ 渠道回复窗口允许
+ 幂等和并发校验通过
```

白名单配置位于 `系统设置 -> AI 接待范围`：

- 白名单开启：除 `ai` 标签外，还必须在会话编号列表中。
- 白名单关闭：不限制会话编号，但仍必须有全局开关和精确 `ai` 标签。
- 缩小白名单或移除 `ai` 标签会取消排队中的实时回复和沉默任务。
- 每条文字和每张图片真正提交前都会重新检查远端标签。
- 全局发送配置缺失时默认关闭。

演练场固定禁止真实 Chatwoot 出站，不受真实发送总开关影响。

## 8. AI 演练场测试

1. 在线路管理完成修改并点击“校验并发布”。
2. 在 AI 接待策略修改全局配置并点击“发布策略”。
3. 新建演练会话，不复用已执行多轮的旧会话。
4. 发送客户消息，检查理解结果、代码计划、固定回答或生成来源、事实核验结果。
5. 已选线路时确认勾选组立即按顺序出现。
6. 使用“测试下一次跟进”推进剩余沉默节点，无需真实等待。

旧会话保留已发送图片、覆盖组、档案和旅程版本，因此不会表现得像全新客户。
