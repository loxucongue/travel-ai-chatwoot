## 当前 V3 的问题

1. `tibet-reception/SKILL.md` 将首次邀请过窄地绑定到“喜欢、认可安排、询问下一步”，将“商量”与不宜邀请过度关联。当前线路 contact_request 的 negative_examples 也包含“先看看或和家人商量”，会压制低中意向客户首次邀请。
2. “问过一次未回应，此后只回答，直到客户明确准备推进”太绝对。应禁止连续催问，但客户提出新核对需求、渠道使用困难或主动回来继续规划时，可以重新承接。
3. 当前话术主要是 LINE ID 邀请。配置允许 Email 不等于 Skill 已教会模型如何接受邮箱、邀请邮件联系和承接“把你的账号给我”。
4. #588 当轮其他月份配置冲突：custom_guidance 要求不匹配转人工，routing 却要求推荐现有线路。需要统一成“说明产品边界、承接需求、推进人工联系”，不能说不存在的九月团已经确认，也不能把客户拉回桃花团后结束。
5. action=handoff 会停止后续 AI。若只问“方便留 LINE 吗”就同时 handoff，客户下一轮发来的 ID 将不再由 AI 自动接收。应区分等待客户选择／提供联系方式和人工已经接管，不能混成一个动作。
6. 后端现在直接合并模型 profile，原文仍在消息记录中。留资设计必须使用真实客户消息及实际交付记录区分“邀请发出、客户指定渠道、收到地址、已交接”，不能从“我有 LINE”推断已经获得 ID。

## 建议改法

### 1. 首次邀请提前到“已有接待基础，并且能说明联系用途”

完整介绍已完成或主要问题已答，客户继续咨询、提供人数、讨论出行月份，即可选择合适节点首次邀请。不要求确定报名或准确日期，也不机械按两轮触发。严重未处理顾虑先回答，不能用联系方式交换答案。

客户说“先和家人商量”但未拒绝联络时，允许一次轻邀请；客户说“先在这里问”“先别加”“不要联系”则尊重相应范围。不是每次提及家人都索取，也不是每次都免邀。

### 2. 通用话术维护接待方法，线路话术提供具体内容

在已有通用话术配置维护六组场景：

| 场景 | 参考表达（优化草案） |
|---|---|
| 正常首次邀请 | 方便留一下您的 LINE ID 嗎？我請顧問接著協助您確認出發安排。 |
| 日期未定、和家人商量 | 您先和家人討論，時間還不用急著決定。方便留一下您的 LINE ID 嗎？之後有想調整的地方，可以請顧問接著協助您。 |
| 其他月份 | 這條桃花行程是3月20日到4月10日，9月的安排需要另外確認。方便留一下您的 LINE ID 嗎？我請顧問協助您看9月適合的行程。 |
| 客户选择 Email | 可以呀，留 Email 就好。方便提供您的信箱嗎？我請顧問用郵件和您聯絡。 |
| 不便加好友、仍愿意收资料 | 如果用 Email 收資料方便些，也可以留信箱，我請顧問用郵件和您聯絡。 |
| 客户主动加顾问 | 可以，這是我們顧問的 LINE ID：〔读取当前配置〕。 |

这些是条件话术，不是每轮都发。其他月份的模板必须保留尚未确认安排的边界；如果客户尚有实质问题先回答。已发完整资料不能伪称尚未发送，不说 FB 发不了大文件，不谎称已寄邮件／已加好友。

顾问当前官方账号、添加链接或二维码应复用可引用的通用话术和素材配置；当前没有可靠账号时落实人工提供，不从旧对话抄员工 ID。无需新建一套配置页面。

### 3. 放宽一次邀请，约束重复追索

- 未问过：有具体用途就可首次邀请，问题放在最后，只选一个渠道。
- 客户跳过邀请问其他问题：先回答，不在紧接下一轮又索取。
- 后来出现新的明确核对需求／客户愿意继续推进：可以一次新的承接，不靠换句话重复催。
- 不方便 LINE：先区分操作困难与不愿留资；客户仍愿意通过其他方式联系时，Email 可作为低负担替代。
- 已给 Email：接收并交接，不再索取 LINE。
- 要顾问账号：提供配置账号。发出账号只是提供入口，不能记成已取得客户联系方式；客户说已加则保留自报状态，顾问确认后才算建立联系。
- 拒绝所有主动联络：停止主动触达；新问题仍可回答。

### 4. 沉默可以包含一次合理的联系邀请

“新价值”不只指又一张新照片，还包括针对尚未解决需求提供下一步人工帮助。#588 的九月安排就是一个可承接事项。未曾邀请时，沉默评估可以围绕这个事项首次轻邀；已经邀请未回应，则不要在三分钟、五分钟连续问 LINE、Email。没有新内容、没有新的承接理由，可以等待或结束。明确拒绝、实际交接后停止主动销售。

沉默本轮不发与永久不再评估分开判断；不能仅因固定 SOP 发完就认定整段需求完成。测试使用真实三／五分钟等待，生产仍遵从实际配置时段和间隔，不能用测试参数覆盖线上开关。

### 5. 系统提示词只补业务目标和动作语义

稳定提示词明确“帮助低中意向客户继续规划，并取得一种联系方式交给顾问”，以及 reply 邀请与 handoff 接管的差别。场景、口吻和正反例放 Skill，不再两边重复几十条规则。

复用已有 memory、消息和交接状态。客户偏好／地址属于客户事实；邀请是否真正发出属于实际交付记录。确有缺口才补最小字段；不新建审核链、多 Agent 或关键词留资状态机。最终输出仍直接发送。

### 6. 同批解决 #588 的其他缺陷

统一目录外处理配置；限制三月适用日期为3/20起；区分拼团升级和独立成团价格；“標間拼住”改成自然“两人一房”的表达方法；减少重复报价和日期；九月仍为候选需求时保留三月日期未定，并记录待确认事项，不擅自覆盖为确定九月。

5. 客户给 Email 就按 Email 交接，不追问 LINE；只答“有 LINE”则继续询问实际 ID；直接要求顾问则立即交接，不强制要求先留资。
6. 沉默时按已发邀请与未解决事项决定是否触达，不连着更换渠道催问，也不把九月需求误记为已解决。

## 验证与预期效果

沿用上一轮八段长对话，补四段：#588 多月份与家庭讨论、Email 分支、客户反向索要顾问账号与搜索困难、已有联系／拒绝／其他渠道偏好。形成固定 12 段，覆盖两条线路。每段连续提问，读取上一轮结果再推进；对可留资场景注入三种不同客户反应：给联系方式、忽略继续问、明确拒绝。保留原始失败文案。

先验证配置与交接代码，再用同组长对话比较两轮候选。最后增加少量未用于改写话术的新表达，检查能否泛化。沉默用真实墙钟等待三分钟、再五分钟，同时核对是否发送、内容、重复邀请及下一任务；停止后不假称第二次触达成功。

建议验收目标（不是当前成绩）：

- 预先标注适合首次邀请且客户未拒绝的测试片段，均出现一次具体、自然的邀请；不要求所有会话都邀请。
- 客户提供有效 Email／LINE／微信后，固定样本全部正确承接并交接，零额外渠道追索。
- 客户要求账号时有真实配置可给；无配置不编造。用户自报“已加”与核实成功分开。
- 联系邀请不造成漏答当前问题，不添加“加好友才报价”的门槛。
- 沉默样本零拒绝后触达、零相邻重复追索；无适合内容时允许不发。
- 非 SOP 回答至少九成人工评为可直接发送；台湾自然度仍需业务顾问复核，不由规则测试替代。

预期得到的是更多合理的首次邀请、更少遗漏 Email、更清楚的交接，以及“其他月份也继续承接”。真实有效留资率要上线观察客户反应才能确认，不能承诺“每个客户都留资”或给出无依据增长百分比。

本次仅分析并形成方案，未修改业务代码、配置或部署；未调用模型，新增模型测试费用为 0。

## 补充：四人原话保留与主动提问

再次读取 #588 后确认，人数话术 `group_party` 已存在于当轮 Skill，模型也在决策 2178 中引用了该 ID。但同时输出了改写后的 text；发送层优先使用 text，因此实际发出的不是配置原文。没有审核器在发送前删掉原话。

当前框架先发整套介绍，介绍期间收到“4位”排队；直到介绍结束才承接。因此原话最后“不过先让我先介绍一下行程”已经不适合直接照发。应明确保留原话主体，只调整过期衔接：保留公司小团定位、4–6人团型和可考虑自组团，不擅自改成泛化确认或新增“独立成团价格一样”。如果人数在介绍之前已经明确，则可用完整人数承接话术，再进入介绍。不能通过这次修改暗中把“不报人数不介绍”设成新门槛。

对于客户已明确要保留的场景原话，适用时优先直接引用；允许改称呼、已知人数、过期的前后衔接，不默认整段改写。这是 Skill 的使用方法，不增加发送后的文字替换器。

沉默评估应允许三类相关动作：补充尚未交付的相关事实；询问一个影响下一步的未知需求；有具体用途时首次邀请联系方式。“只有新资料才能触达”过窄。#588 可以澄清是否主要考虑九月、是否仍偏好不上珠峰；人数4位已知，不再问人数。每次只选最有用的一项，不连问多个问题，也不在已有邀请未回应后连续催促。

#588 当前 next_check_at、next_check_minutes 均为空，首次沉默决策明确 stop_followup=true；继续等待不会自动产生新任务。现阶段未恢复这个既有会话的跟进，避免把分析当成已修复或偷偷重放旧会话。
