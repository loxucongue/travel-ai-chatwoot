# 接待后台重设计：页面、配置归属与执行合同

状态：设计定稿，附可点击原型；尚未接入业务 API、替换现有页面或部署。
依据：2026-09-27 当前代码与用户最新确认。本文细化并接续 `script-driven-reception-design-20260927.md`，不改变其业务目标。

## 1. 本轮设计决定

配置收敛到四个入口：**通用接待、线路接待、通用知识与素材、连接设置**。演练、会话、人工待办属于工作入口，不混入配置导航。统计总览保留在工作区。

最常见的维护操作应只有两条：

- 改一条线路：进入线路接待 → 选择线路 → 改完整介绍或场景话术 → 查看发送预览 → 保存并生效 → 新建演练。
- 加通用回答：进入通用接待 → 通用话术 → 添加适用场景、话术和素材 → 保存并生效。无需修改代码或手写 Skill。

不另设发布审批、规则引擎、可配置阶段状态机或审核中心。不把旧字段换名字后全部搬进高级设置。后台唯一编辑源组合成运行时 Skill；Skill 文件只保留工作方法。

## 2. 导航与页面布局

| 区域 | 一级入口 | 二级内容 |
| --- | --- | --- |
| 工作 | 演练场 | 新建客户、演练记录、历史批量回放 |
| 工作 | 客户会话 | 对话、介绍进度、待回答问题、人工状态 |
| 工作 | 人工待办 | 待核实事项、联系方式、顾问接手 |
| 工作 | 总览 | 现有统计；本轮不扩展指标 |
| 配置 | 通用接待 | 首次开场、通用话术、留资与交接、沉默跟进 |
| 配置 | 线路接待 | 入口与概况、完整介绍、场景话术、事实与素材 |
| 配置 | 通用知识与素材 | 服务事实、通用素材、官网来源 |
| 配置 | 连接设置 | 渠道、模型、顾问通知、维护工具 |

通用接待的身份与语气放在首次开场页下方，不再单设“目标”“语气枚举”“自定义规则”三个近似文本框。每页标题下面明确作用范围，页底一个“保存并生效”，旁边显示未保存状态。历史记录用当前页抽屉，不另建版本中心。

线路页采用顶部线路选择器＋四个页签。完整介绍为左侧顺序列表、中间内容编辑、右侧客户视角预览。场景话术为可搜索列表与同一编辑器。小屏幕改成单列，预览通过页签展开，不压缩三栏。

## 3. 通用接待：字段与行为

### 首次开场

| 字段 | 编辑方式 | 生效方式 |
| --- | --- | --- |
| 开场消息 | 可排序的文字、图片、视频、文件块；引用通用素材 | 首次客户消息后按原文和顺序发送，不经过模型改写 |
| 消息间隔 | 一个非负秒数 | 上一项提交完成后计时；不计文件上传耗时 |
| 品牌身份 | 品牌名、顾问称呼、一段语气说明 | 提供给主 Agent；不改变固定开场文字 |

页内固定说明：“同一客户只开场一次；演练中一个会话视为一个客户。客户首条消息里的线路和问题继续处理。”不再提供问候词、正则、字数、已选线路等开场条件。

真实客户范围采用现有账户＋收件箱＋联系人身份，防止把另一个渠道的陌生联系人合并；缺少联系人 ID 时仅能退回会话身份并记录原因。已有客户历史视为已接待，不补开场。不批量重放历史消息。演练身份始终是 session ID。

### 通用话术

统一编辑器的必填项只有：名称、适用场景、话术原文。问法示例、排除场景、适用条件、关联素材可选；启用/停用直接可见。

- 一个场景一条可复用话术，例如集合说明、入藏函领取、客户表示考虑。
- 不要求填写关键词、模型 intent、fact ID、优先级数字或内容组 key；内部 ID 自动生成。
- 原文优先，主 Agent 可结合实际问题摘取、拼接、调整衔接，不引入事实外承诺；无二次模型审查。
- 线路页以“继承通用”标记展示相关通用话术，点击编辑返回通用来源。建立“本线路专用版本”才产生专属条目，保留显式来源 ID。
- 同场景的专属版本覆盖通用版本；其他通用话术仍可用。不要通过比较话术标题猜覆盖关系。
- 搜索按名称/场景/原文；复制保留素材引用，生成新 ID；被引用的话术可停用，删除前显示引用位置。

### 留资与交接

编辑允许联系渠道（LINE、微信、电话、Email、WhatsApp）、索取联系方式话术、客户拒绝后的承接话术、收到联系方式后的交接话术，以及少量“哪些事项请顾问处理”的说明。

时机由主 Agent 结合客户问题、兴趣和既有联系方式决定。不保留“回答两个主题后索取”“人数和日期齐全才可留资”等固定门槛。已收到联系方式或要求真人时交接，是执行动作，不是后台可随意拼装的 flow。

顾问账号与推送身份在连接设置维护，此页只提供跳转。顾问通知成功显示“接口已接受”，不写成“手机已收到”。

### 沉默跟进

唯一的全局节奏：启用、首次等待分钟、后续等待分钟列表、有效时段与时区、每日触达上限。时间表示距上一次客户可见回复结束的等待时间，不与“入组后的绝对分钟”混用。

候选话术仍使用统一编辑器，场景如“住宿顾虑未解决”“需要和家人讨论”。线路专属补充放在线路话术中，标记可用于沉默跟进；不复制一套线路 SOP 到此处。

到期只产生评估事件，同一个主 Agent 决定发送/等待/结束。没有相关新价值就结束，不能固定发完次数。拒绝主动联系、已留资、已交接时停止。客户主动回来仍正常答疑，不自动恢复营销。

## 4. 线路接待：字段与行为

### 入口与概况

线路名称、客户可见名称、启用状态、来源页面、简短介绍。广告入口列表包含“入口名称、广告自动消息、可选的已接入渠道标识”。只展示当前渠道实际提供的广告字段，不能画出尚未接入的广告 ID 功能并声称自动识别。

入口消息匹配仅做空白、大小写等格式归一，不做模糊关键词选线；同一条入口配置不能绑定多条线路。其他文本由主 Agent 理解。入口是意向来源，客户在同条消息里明确否定或更正时，以最新明确表达为准。未知线路先匹配，不默认发送第一条线路。

### 完整介绍

编辑整套介绍，不再编辑“线路资料”“接待主线”“独立 SOP”三份文本。

每组：组名称、启用、可排序消息块（文字/图片/视频/文件）、组后等待秒数（默认继承）。整套只有一个组内间隔与一个默认组间间隔；某组的例外直接显示在该组，不另设沉默时间节点。

每块直接引用话术或素材；固定介绍以原文执行。引用话术时显示来源并回源编辑；解除引用后明确变为独立内容，不在背后同步两份文本。新增组支持复制、上移/下移、删除；行程图应在景点、酒店、车辆照片之前，预览展示实际顺序。

右侧显示完整客户视角、总消息数、各组间隔、最低等待时长和“整套介绍结束后集中答疑”。预计等待计算：各组 `(块数−1)×组内间隔` 加除最后组外的组间等待；网络及渠道发送耗时另计。已知慢发送不能保证严格每两秒到达。

不提供“插问时中断/继续”的新开关。业务已确定整套发完后集中回答，所有线路共用这一合同。客户直接索取某张照片时仍可单独答疑，不强制重新开始介绍；已经完成介绍的线路不会每次追问都重发。

### 场景话术

与通用话术完全相同的编辑器，默认展示本线路条目，另一个筛选展示继承的通用话术。增加可选用途“普通问答 / 沉默补充”，用途不是硬性 Flow。

例如住宿、价格、多人、供氧、日期不确定。真实条件写在条件字段或原文中；不让运营写正则判断客户。

### 事实与素材

同一页两个切换视图：

- 事实：主题、事实正文、适用条件、来源；价格、住宿、日期都在此单源维护，不再有独立价格页写另一份事实。
- 素材：缩略图/文件名、类型、所属线路、用途、替换、引用位置；支持图片、视频、PDF。通用素材通过选择器引用，无需复制上传。

素材选择器默认本线路，可切到通用；另一条线路的行程图不混在默认候选。选中后拖动排序，支持可选图片说明。一个素材可供多条话术/介绍使用。替换保留素材 ID、生成新的文件版本，历史执行引用不变。被引用的素材先解除引用或选择替代项才能删除；这只是维护引用完整性，不是话术审核。

## 5. 通用知识与素材、连接设置

通用知识只存可以跨线路使用的事实，包含主题、事实、条件、来源、启用。路线限定事实回到线路页。官网来源展示 URL、上次获取、变更内容，由维护者选择并保存到事实库；不自动把所有网页复制成全局事实。引用事实的使用记录移到对应接待详情。

连接设置只保留真实连接和运行维护：

| 页签 | 内容 |
| --- | --- |
| 渠道 | Chatwoot 地址/账号/凭据、收件箱、Webhook 连接状态、现有接待范围与发送开关 |
| 模型 | 当前 V2 实际模型及配置来源；能保存的字段必须接到实际调用者；环境变量管理的字段只读并明确说明，不能把旧 Adapter 表单冒充 V2 模型设置 |
| 顾问通知 | 接收顾问、机器人身份、通知方式及一次测试结果；不重复留资话术 |
| 维护工具 | 历史导入、标签映射、现有成员管理、配置变更记录。展开后使用，不新增权限系统 |

同一全局发送开关只有一个数据源，页头快捷操作与此页同步。不在每个话术页重复真实发送开关。旧 Adapter 若仍服务 V1，明确放在维护工具下的 V1 区域；确认无调用后再删除。

## 6. 保存、生效与预览

| 内容 | 保存后的生效点 | 进行中的接待 |
| --- | --- | --- |
| 开场 | 下一位首次进入的客户 | 已开始的开场继续原快照，不重复发 |
| 固定介绍与素材 | 下一次启动该线路介绍 | 已开始的整套介绍使用启动时快照 |
| 通用/线路话术、事实、语气 | 下一次主 Agent 开始处理 | 已在生成的当前轮使用原上下文快照 |
| 沉默时间 | 新安排的候选节点 | 已安排节点保留原时间；到期读取最新启用与联系状态，不批量补发 |
| 停用沉默/人工接管/停发 | 下一次提交前立即检查 | 取消尚未提交项目；已经提交的无法撤回 |

一个按钮“保存并生效”，不是“保存后还需要发布”。保存成功显示版本和生效范围，失败保留编辑内容；未保存离开页面提示保留/放弃。并发编辑只提示版本冲突，不静默覆盖。版本历史“恢复此版”创建新的当前版，历史不抹除。

“用当前配置演练”创建新演练客户，显示具体版本，不续用旧会话冒充新客户。草稿本地预览和已生效配置演练分开标注。

## 7. 介绍执行与问题排队

### 状态与持久化

尽量复用当前 enrollment、job、消息和 delivery 记录；不新建通用工作流引擎。

一次介绍保存 `run_id / route_id / snapshot_version / status / next_item / last_submitted_at`。状态只需 `sending / completed / interrupted / failed`。待答消息保存原 ID、文本、时间、所属介绍 run、处理批次和状态 `waiting / answering / answered / handed_off`。优先放在现有任务状态或 JSON 数据字段，开发时以查询与事务需求决定字段迁移，不强行为“零改表”做内存队列。

首次开场使用发送记录判断已提交，而不是“历史没有 assistant 就再发”。第一条消息仍登记为待处理；已知线路启动介绍，其附带问题加入待答；未知线路进入匹配问答，确认后只启动一次介绍。

### 普通消息

1. 入库并去重，取消旧沉默节点。
2. 正在介绍时，保存为待答。介绍继续，不标记这条客户消息已回答。
3. 介绍最后一项成功提交后，在同一事务中结束介绍并创建一次答疑任务。
4. 主 Agent 接收本批全部原消息和已经发送的介绍；保留不同问题，人数等更正以最新明确表达为准。
5. 回答成功提交后才把本批标为已答。生成期间来的新消息留给下一批，不会被批量清空。

发送端所谓“完成”是现有渠道可验证的提交完成，不伪称客户已读或设备收到。结果未知进入异常处理，不能跳过后假定成功。

### 紧急事件

正在介绍时，普通问答可以等待，但事件识别不能等待整套结束。复用主 Agent 的客户事件输出，设一个“正在介绍、只更新状态、不生成普通回答”的调用模式；不增加独立分类器/审核器/中文关键词表。没有可靠渠道事件时，这一步仍有一次模型延迟，不能承诺零延迟打断。

| 事件 | 行为 |
| --- | --- |
| 停止本次介绍 | 取消未提交介绍；不擅自解释成永久拒绝全部联系 |
| 拒绝主动联系 | 停止介绍与沉默，保留后续被动答疑；同轮明确问题仍可回答 |
| 明确改线 | 结束旧介绍，保留已知客户信息，启动新线路；队列保留原线路语境，不把旧线路价格问题套到新线路 |
| 真人请求/顾问接管 | 结束介绍；待答问题与已发资料进入交接摘要，不再自动销售 |
| 提供有效联系方式 | 交接，不为发完介绍继续推送；不误把电话号码咨询当成客户提供号码 |

事件更新与下一项发送使用同一会话的顺序锁/现有租约和任务版本检查。已知有新消息待事件识别时，下一项短暂等待识别完成；普通事件确认后继续，不重头发送。人工接管和后台停发有直接状态事件，无需等模型。

保留“已停止后不再提交”和实际发送去重，是执行正确性，不恢复任何对最终话术的审查。事件解析失败时暂停后续介绍并生成可处理状态/待办，不猜客户只是普通问题。

### 异常与恢复

介绍明确失败后，不让问题无限等待：记录已成功项目与失败位置，结束当前介绍执行，已有待答交主 Agent，缺失资料另建待办。若发送结果未知，则交人工确认，禁止无依据重发。服务重启按实际交付记录恢复，重复 webhook 不重复入队。模型回答失败保留待答并复用人工待办，不自动发送失败承接语。

答疑后有强意向即可自然留资。介绍完没有问题时也可让主 Agent 判断是否适合留资；不要把留资固定塞进每条线路最后一组而无视客户拒绝。随后才安排沉默，不从介绍第一条开始计时。

## 8. 演练与会话详情

保留客户聊天主界面，右侧“接待详情”显示：入口线路来源；当前线路；完整介绍进度（第几组/共几组、下一条时间）；待答原消息列表；已回答批次；联系方式/人工状态；本轮实际话术与事实来源、版本、模型耗时与调用数；实际提交结果。

清楚区分“给模型提供过某条话术”和“本次确实选用了该话术”，后者只有存在记录时展示，不能用加载列表冒充命中。普通问答直接展示最终正文，不再画审核→改写→复核流程。

演练提供“推进到下一发送项/下一沉默时间”的虚拟时钟操作，仍使用与正式相同的业务函数，只替换时钟与发送适配器。不能让演练的队列和真实队列再发展成两种语义。

业务复核可以标“可直接发送/需修改”并留言；这是事后人工反馈，不参与实时发送门禁。

| `/sops` | 配置迁入线路介绍/沉默后删除编辑器；保留正在执行的快照与历史发送记录 |
| `/evaluation` 旅游素材 | 根据归属迁入线路素材/通用素材，引用同一文件 ID，不复制上传 |
| `/evaluation` 全量回放 | 演练场的历史回放，不占一个配置入口 |
| `/knowledge` | 通用知识与素材；知识使用日志移到会话详情 |
| `/settings` Webhook | 渠道详情，合并连接状态 |
| `/settings` AI Adapter | 检查真实调用者；V1 专用归维护工具；V2 展示实际模型来源 |
| `/settings` 通知 | 顾问通知，保留已有配置 |
| `/settings` history/mappings/users/audit | 维护工具，不新增权限与审计系统 |
| `max_characters/max_images_per_turn` | V2 不作为回复裁剪/整套介绍截断；真实渠道限制只用于分段发送 |
| `ask_after_answered_topics/require_party_size/require_departure_window` | V2 取消机械留资门槛 |
| `stage_journey/mandatory_send/model_max_attempts` 等 | V2 配置删除弃用字段及独占代码，不留无效表单 |
| `opening_message/opening_messages/opening_items` | 迁移成一个有序消息块来源；旧值优先级按现有 opening_items 优先，冲突需在迁移报告列出 |

删除写入口前做一次配置映射清单：原 ID、内容、目标位置、引用数、是否生效。无法归类的自定义 SOP 节点不丢弃，迁移报告列出，逐条落位或明确淘汰；“最后写入时间较新”不等于业务正确，冲突不得静默覆盖。

旧 URL 可以跳转到新页，旧写 API 不继续维护第二份配置。业务端仍共用的读取/执行模块先迁移调用者，再删除。保留真实历史记录不等于保留弃用逻辑。

## 10. 开发拆分与完成定义

按可验证边界分提交，先本地替换原 V2，禁止另外造 V3：

1. **唯一配置源**：建立通用话术结构、素材归属、介绍消息块映射；对现有数据生成迁移报告；运行时 Skill 读取同一配置，模型真实配置来源可见。
2. **四个配置页面**：复用现有 React/Query/组件；实现统一话术编辑器与素材选择器、介绍排序和预览、保存/历史；删除旧重复页面和独占写入口。
3. **共同接待执行合同**：首次开场继续处理首条消息；广告入口；介绍快照、问题队列、紧急事件与并发提交边界。正式/演练共用核心函数。
4. **接待详情与业务验收**：进度、待答、来源和耗时；配置到发送的跨层测试；必要的小批模型样本单列效果，随后按已授权发布流程交付。

| 验收 | 必须观察到的证据 |
| --- | --- |
| 配置开场 | 新客户各一次，同客户重复问候不重发；文字及素材逐项相等；首条问题仍在处理链 |
| 固定线路介绍 | 两条线路各按配置顺序、间隔发送；变更配置不改进行中快照；不受问答图片上限截断 |
| 插问排队 | 第一/中间/最后一组各插问，整套之后全部处理；并发最后一条不丢；重启不重复 |
| 紧急事件 | 停止/改线/人工/留资各能中止未提交项；原待答得到回答或出现在交接摘要 |
| 话术与事实 | 通用＋线路话术生效、专属覆盖、停用移除、复合问题完整；无最终文案审核请求 |
| 素材引用 | 本线路＋通用可选、预览顺序一致、替换只影响未来、缺失不记成功 |
| 主动留资 | 问题解决后能合理提出一种联系方式；拒绝后不纠缠；收到后实际创建交接 |
| 沉默触达 | 介绍及答疑完毕才计时；有新价值才发；拒绝/已留资/人工/新消息取消 |
| 页面清理 | 每类配置一个写入口；旧导航跳转；独占死代码删除；V1 共享调用未破坏 |
| 保存生效 | 草稿/生效版清楚、失败不丢输入、历史恢复可查、演练明确实际版本 |

此次原型是交互设计证据，不能替代上述运行时验收。原型素材是有标识的占位图；示例文字不覆盖现有业务口径。
